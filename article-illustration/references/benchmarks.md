## 二、图落在哪些小节

美团技术团队三篇逐节统计，图集中落在三类小节：

| 小节内容 | 配图情况 |
| --- | --- |
| 讲结构、讲模块划分、讲架构全景 | 每节 1 图 |
| 讲流程、讲阶段推进、讲处理路径 | 每节 1 图 |
| 给实测数据、给效果对比、给性能表格 | 每节 1 到 2 图 |
| 讲背景、讲挑战、讲结论、列参考文献、团队招聘 | 不配图 |

一篇 28 个小节的文章，有 19 张图，落在其中的 16 个小节里。首节（标题与摘要区）配有 2 张图，用于给出全篇的总览结构。

本库执行同一规律：每节 0.5 到 0.9 张图，讲结构与流程的小节优先配，讲背景与结论的小节不配。

## 三、容器宽度

站点把 mermaid 代码块渲染成 svg，svg 的宽度是图区宽度，图形宽度超出时浏览器等比缩小，字跟着一起缩。下表为 2026 年 9 月在真实页面上的量测结果：

| 场景 | 正文栏 | 图区 |
| --- | --- | --- |
| 1440px 视口桌面 | 740px | 706px |
| 768px 竖屏平板 | 386px | 352px |
| 360px 视口安卓机 | 330px | 296px |

桌面端正文栏实测 740px，图区 706px。最窄的手机上图区 296px。

手机上的实际字号：

```
有效字号 = 16 × 296 ÷ 图的自然宽度
```

16 是 mermaid 节点文字的默认字号。按此换算：

| 图的宽度 | 手机上字号 | 判定 |
| --- | --- | --- |
| ≤ 473px | ≥ 10px | 合格 |
| 473 到 592px | 8 到 10px | 勉强能看，尽量收窄 |
| > 592px | < 8px | 看不清，必须改写法 |

## 六、一次修复的对照

《缓存行与伪共享》一文的机制图，被测 AI 第一版画成横排 5 节点，实测宽度 769px，手机端字号 6.16px，判定不合格。同一份内容改成竖排后宽度降到 400px 以内，字号回到 10px 以上。

## 七、外链图片的可达性

图片要以外链引进，地址必须在浏览器里能直接取回。实测：

| 图源 | 结果 |
| --- | --- |
| GitHub 仓库图片 `github.com/<仓库>/raw/<分支>/<路径>` | 可外链，46 到 144KB |
| RocksDB 官网 `rocksdb.org/static/images/` | 可外链，19KB 线条图 |
| Cloudflare 博客 `blog.cloudflare.com/_image?href=` | 可外链，按宽度参数取回 |
| 美团技术团队 `p0.meituan.net/meituantechblog/` | 可外链，单张 1.1MB，注意体积上限 |
| Brendan Gregg `brendangregg.com/FlameGraphs/` | 可外链，132 到 747KB |
| perfmatrix `perfmatrix.com/wp-content/uploads/` | 可外链，16 到 154KB |
| preshing `preshing.com/images/` | 可外链，4 到 21KB |
| 维基共享资源缩略图 | 浏览器可加载，脚本抓取遇限流 |

主要来源都能直接外链，不需要先下载到本地。

## 八、校准命令

重跑密度统计：

```bash
python3 bench_density2.py         # 逐篇统计字数与图数
python3 bench_sections.py         # 逐节统计图落在哪里
```

重跑资源可用性：

```bash
python3 verify_assets.py          # 逐张量尺寸与体积
python3 probe_hotlink.py          # 逐项测外链能否取回
```

重跑 mermaid 宽度：

```bash
python3 scripts/audit_mermaid.py --json report.json
```

中间脚本放在 `.agent/tmp/illu/` 目录下。
