# 文章配图

图为理解服务。每张图回答一个用文字难以高效讲清的问题，回答不了任何问题的图是装饰，装饰一律不加。

流程三步：定位插图位、找现成图、找不到再自绘。执行保持快：按直觉画，渲染看一眼，不顺眼就改。判据以观感和读者视角为主，`references/` 里的实测数字是翻阅用的参考，不当作必须执行的步骤，脚本只在拿不准时兜底。向文章插入图的编辑，锚点选图位前后的短句或标题行；编辑工具要求 old_string 前后各有 3 行物理行上下文，文章又是段落一行制，单行或两行的锚点会被守卫直接拒绝（报「内容太短」），构造锚点时直接把范围扩到图位相邻的物理行（空行、相邻段落、图块围栏都算行）；锚点确实构造不出来才改用整文件重写，不反复重试同一形状。

给一批文章补图时，选文用全量口径：`python3 scripts/coverage_stats.py "<文章目录>" --list`（目录写绝对路径）按路径打印每篇图块数、无图文章排最前，只手写 shell 管道数图会把反引号代码块当命令替换执行出错误清单。使用者只给「优化哪类内容」没给目录时，先在常见文章位置里搜（当前目录、docs/、articles/、posts/、notes/ 这类常见名字），用 coverage_stats 的清单做候选，配图前把选出的文章清单报给使用者确认再动笔，识别不出候选就把需要的目录说清楚，不凭空猜路径。从上往下选文前先读 `references/reviewed.md` 台账，已有判定结论的文章直接跳过，循环不重读重判；台账的理由列同时是已插图清单，同主题姊妹篇配图前先看里面已经插过什么图，同一张机制图不在两篇文章里重复出现，姊妹篇各自配文字里缺的那一块，角度错开。每轮对一篇文章的最终判定（配了图或判定无需配图及理由）当轮回写台账。判定插图位时先问「这一节读者缺了图会卡住吗」：机制节里已有对照表、边界节罗列不构成对比、验证节写的是步骤清单，这些都不缺图；一篇 200 行的概念文配一到两处足够，处处都图是过度，过度与缺图都是错。插图落位后把图前引出句当文章的一部分写：引出句引出图回答的问题，图后一段收束结论，两边不重复；落位段落原本的首句被图让位时，重读一遍首句与图的衔接，删掉由图承担了信息的那半句。

## 边界：只做图，不做文字优化

本技能改的只有图与图解文字（图前引出句、图后收束句）。文章的段落结构、概念解释、举例质量、表达通俗程度属于写作维度，不在本技能范围内，发现问题也不动正文——越界改正文会与正在改写作的会话撞车，几百个会话并行时这是主要的覆盖来源。

通读全文发现文章本身有问题时，记下来报给使用者，不要顺手改。需要文字与图一起优化时，升级到 `内容治理技能` 的存量全量优化，它把修补生成痕迹、补深度维度段、补篇幅、补配图合成一轮做，并有认领锁与内容指纹防并行覆盖。本技能负责那一轮里的配图判据。

## 第一步 定位

通读全文，下面五类段落优先考虑放图，其余段落不加：

1. 抽象结构：模块、层次之间的静态关系
2. 并发与时序：谁先谁后、消息顺序
3. 状态变迁：状态机、生命周期、模式切换
4. 数据流向：数据从哪来、经过什么变换、存到哪
5. 多维权衡：三个以上选项在两个维度上的位置

最高产的插图位是双路径结局对比：同一事件两种做法，各走一条短链到不同结局，顶端分岔底端对照，一张图同时回答「差在哪」与「为什么」。机制节里「错误做法与正确做法」「有防线与无防线」成对出现的段落，优先按这个形态出图。并列的一对是数字对位：同一指标在改进前后的两个值、或同一事件在两层的两个指标各走一条链，竖排单链节点带层别前缀与数值，虚线边点出层间关系，一层指标归零掩盖另一层指标恶化这类「错误移位」的案例回流，按这个形态出图。竖排的第三种是谱系阶梯：文法谱系、能力等级、版本演进这类有序档次，竖排单链逐级排列，节点写「名称＋约束对象」，边写升级条件，散在文字里的强弱关系收进一张图。

两个对象的简单对比用表格，步骤少又没有分支的流程用编号列表，单一维度的数字用文字，这些场景不加图；反过来，小节里已经有表格不代表不需要图——表格给的是维度对照，过程与结局的路径仍在文字里时，路径值得画一张图。文中已有图先逐张过一遍收尾四问：答非所问的修，与文字重复的删，删图时把图前的引出句一并删掉；剩余插图位再走找图与自绘，修图与画图用同一套直觉。

## 第二步 找现成图（先中文后英文）

**每处搜索走两轮**：第一轮用中文核心名词加「架构图」「原理图」「流程图」「示意图」，第二轮才用英文名词加 figure、architecture、diagram。同名概念两种语言都有图时取中文图——中文读者扫图先看标签，中文图省掉一层翻译。只能用英文原图时，图注必须带关键术语的中文对照（如 F0=第 0 个前向块），只写来源不算对照。**主题贴切永远在语言偏好之前**：技术文章的主图必须是文章主题本身（IT 实物照片、官方架构图、机制图、实测曲线、界面截图），检索词直接用主题的技术名词；生活器物照片（当铺、茶楼、杆秤一类）只作比喻段辅助插图，每篇最多 1 张，比喻段也要有幽默感与理解加成，但不承担主图职责。中文图常见出处：技术团队博客与公众号（美团技术团队、字节跳动技术团队这类）、中文技术社区专栏、论文中文版与配套仓库的 images 目录（如 raft-zh_cn）、国内厂商官方技术文档。

每一处都先搜，覆盖面到三面都看过再下「无现成图」的结论，三面按文章领域取材：主题的代表文献与标志作品、同主题的同类作者与竞争出品方、主题所属领域的官方或权威机构出品，漏掉一面会把有图判成无图、转去自绘。查 `references/assets.md` 的已验证清单，没有对得上的再用 `web_search` 按主题搜（搜索词用领域核心名词加 figure、architecture、diagram 这类图类词），命中候选页面后按 `references/sources.md` 的分级判源，用 `scripts/find_images.py` 提取候选。三面搜完仍无对位候选时，把「这一处想回答什么问题、各自找过哪些出处、为什么不对位」整理成来源推荐报给使用者，由使用者从熟悉的作品与站点里补线索，或确认直接自绘；这轮交互拿到的线索与结果回写 `references/sources.md`，下次同领域不再重复问。真实模块边界与比例、产品界面、命令行输出、监控面板、论文实测曲线、厂商硬件结构，自绘会丢信息，只能用现成图。怀疑脚本过滤过严的触发条件有两条：候选清单为 0 张，或者候选合计数量少于页面里能看到的图数（数一数 HTML 原文的 img 标签再对账）。两种情况都翻页面 HTML 原文核对再下「页面无图」的结论；位图与矢量图的宽度声明都是显示宽度，不是自然宽度，不得按声明宽度硬过滤，矢量图清晰度由 viewBox 决定可任意放大，脚本已按此实现。候选都没有对得上的（主题图缺失、画风不合、只有循环无验证分支这类）才自绘；判「不采用」时把淘汰原因在心里过一遍收尾四问，淘汰的图不写进文章。现成图还要过一问：图里有没有能证明文章论点的证据？截图类候选最容易栽在这一问上——画面是原始输出的截图，内容却不包含要论证的那个现象（比如十六进制视图里没有操作码、监控曲线里没有故障时段），这样的图与文章论点无关，不因「主题对得上」而采用。**底色与夜模式（2026-09-28）**：白底或浅底图优先，透明底位图与深底截图能避开就避开——站点夜模式正文底近黑，透明底图的黑线黑字画在暗底上直接隐形，深底截图整块融进页面。站点渲染端已给正文图片统一铺白底兜底，透明图因此仍可见，但找图时仍按白底优先、透明与深底靠后排序；终端截图类（黑底白字）保留时在图注注明「深色终端输出」。

三条底线：地址必须 https；含密集文字的截图要宽到能看清字；图注写明来源页面名称与地址，许可要求署名时带上作者与许可名称，写法照 `references/sources.md` 第七节的引用样例。命中候选图后顺手核一次出处：图的来源与文章列出的来源条目（frontmatter 或正文标注）对不上号时，逐条 curl 摘要页核标题，主题无关的是错引，改正后再插图；来源清单只有标题，没有核过内容，不能当作已经核对的凭据。核出处连死链一起看：curl 返回 000 是域名失效，从同主题可达文档（厂商官方 docs 优先）里选内容对得上的替代源改正，wayback 取不到就不留死链；返回 403 时带浏览器 UA 复核一次，仍 403 是反爬拦截非死链，链接保留并在台账注明，按死链处理会错杀可达来源。返回 200 不等于可达：Cloudflare 挑战页等拦截页也返回 200，判可达必须核页面标题或正文特征（标题是「Just a moment...」这类就是拦截页），探到状态码就下结论会把挑战页当有效来源写进文章。错引改正的替代源同样逐条核标题后再写：改正引文先确认正主的发表渠道（会议、期刊、厂商官方页），从渠道取地址，不从记忆里报 arxiv ID，改正本身可能引入新的错引，实测连踩两次（TFX 是 KDD 2017 系统论文无 arxiv 版，两次按主题搜 arxiv 分别命中 Automata 验证与 SURF 强化学习）。404 与 403 分开处理：404 是路径失效，从同站导航找改版后的新路径（tensorflow.org 的 guide/ml_metadata 改版为 guide/mlmd 这类）；403 按下述反爬处理。没有 arxiv 版本的系统会议论文（OSDI 这类）引用地址用会议官方页，按论文主题搜 arxiv 会命中同名术语的无关论文。现成图与候选段落的「档次」要对位：讲文法谱系的段落，配图里只能有文法这一档；图里多出类型系统、定理证明器这类更高档次的，是主题相邻不是主题匹配，采用即答非所问。实测过的来源把结论回写 `references/sources.md`，量过尺寸、看过内容的图回写 `references/assets.md`，无图结论与有图结论同样有价值，避免下次重复搜同一页。位图外链的页面验收与 mermaid 分开做：mermaid 用逐图截图脚本，位图用逐张元素截图（等图绘制完成再截，过早截图会得到半张空白），两张都过了再跑 `scripts/audit_bitmap.py` 复查地址、宽度与来源标注。

## 第三步 自绘

自绘用于抽象结构、时序、状态、数据流向、多维权衡五类内容。默认工具 mermaid；图是泳道化流程、多级泳道主干、带降级旁路的治理链路、分阶段合流数据流这四类形态之一时升级 archify 精绘（作图、布局修复与 SVG 导出流程见 `references/patterns.md` 的「Archify 精绘」节，工具本体随文章仓库的 projects/archify 分发）。动笔前先用收尾四问的第 1、3 问预检：删掉不损失信息、或与段落文字高度重合的构思，改画文字里缺的那一块（数值前后变化、结构对照）再动手；画完才发现是复读，返工远贵于预检。九类图型与模板查 `references/patterns.md`，画之前记五条直觉：

1. 主干竖排用 `graph TD`，需要并列或分叉时先想能不能分层竖排；分叉、并列、长标签都会把图撑宽，显得太宽就先缩短标签、再减分支。分叉图每个分支只留一条链，链上节点标签压到 6 字以内、一条 `<br/>` 换行为限，分支各走各的、不要在分支中途合并再分叉，19 字长标签能把 2 支分叉撑到 773px 超线，压到 6 字后同结构 362px 达优。压字时连线标签一并看：分叉公式按节点标签算宽，连线标签长于节点标签时实际渲染更宽，本轮实测 9 字节点配 6 字连线标签量出 510px，两处同压到 6 字内 409px 达优。
2. 标签是一眼读完的中文短句，术语保留英文；连线带语义，只有单一关系才用裸连线；节点标签自解释，跳过正文也能看懂。
3. 时序图参与者一多就横向撑开，参与方多时改画竖排流程图，用节点代表各方。
4. 长链横向铺开会把整图压成一条，页面按宽度缩放后字号小到读不了；带流向的长序列改竖排，链上逐节点加事件名前缀能保住可读性。子图内部 `direction` 在子图与外部节点有连线时会被忽略，按外层方向渲染，别指望子图方向救宽图。
5. 不用 emoji，不自定配色。底色按站点夜模式可读约定：mermaid 自带主题正常出图即可，不自定深底；页面渲染端已给位图铺白底，深底自绘图没有意义。线条与文字用深色（近黑），底保持浅色，与站点两种主题都兼容；深底白字的终端风格图只用于终端输出类内容。

写完看一眼渲染：一屏能看完主干、手机上文字还能读、视线不折返，就过；不顺眼就改，改完再看。拿不准才用 `scripts/audit_mermaid.py <文件>` 量一次，量出的问题按上面的直觉修。

插图插进正文时只围绕图块动，紧邻的引导句、列表引导行一个字不动；replace 的旧文与图下方内容的衔接处要完整核对，插完把图前图后各读一遍，防止吞行。

多会话并行时同一篇可能被另一会话先改，所以写入前两道锁都要过。

第一道独占锁，保证同一时刻只有一个会话在改这个文件：

```bash
python3 scripts/concurrent_guard.py lock <文章路径> --agent <你的会话标识>
```

拿不到锁（退出码 3）说明有人在改，换一个目标或等锁过期，禁止等待后直接写入。锁默认 30 分钟过期，确认对方已中断才用 `--ttl-min 0` 抢占。改完必须 `unlock`，不释放会堵住其他会话。

第二道内容校验，防的是你读完全文、图也画好、准备插入时别人已经写完的情况，此时锁可能已经释放：

```bash
FP=$(python3 scripts/concurrent_guard.py fp <文章路径>)   # 读完全文后立刻记
python3 scripts/concurrent_guard.py check <文章路径> --fp $FP   # 每次写入前
```

check 报「内容已被改动」（退出码 4）时，重读全文，把外部改动当候选成果走同一套验收（核来源标题、文章页截图、audit_bitmap 复查），通过就只补台账与图源清单，不重做编辑，同一张图不插两遍。确认要丢弃外部改动才重新 lock 后写入。

两道锁的关系：锁管「同时写」，指纹管「改完覆盖」。只认锁会在锁释放后覆盖别人成果，只认指纹会在两人同时读到同一版本时互相覆盖。几百个会话并行时两道都要。

lock 与 fp 都在仓库根的 `.concurrent-guard/` 下记状态，脚本会自动把该目录写进 `.gitignore`。git commit 的退出码可能被管道末端命令掩盖成 0，提交是否真实发生以 `git log` 为准。

## 验收：截图确认

文章页上逐张截图确认，编辑器预览不作数：加载文章页，等每张图渲染完成，逐张单独截图并逐张过目，核对三件事——内容画对了吗、渲染完整吗（底部与两侧无裁切）、观感过关吗（收尾四问照做）。外链图同样逐张截：外链有防盗链、尺寸超限、加载失败的可能，浏览器里没显示出来就是没通过。外链位图截到的是空白或半张时，先区分两种成因：页面没加载对（数图块为 0、骨架屏未消失）与图还没下载完（img 元素已出现但内容为空）。截图脚本对外链图已改为等 img complete 且 naturalWidth > 0 再截，正常不再出现这类空白；仍出现时按成因归属处理，页面没加载对就核对路径与服务，脚本异常就先修脚本再重截。截图保存到固定的验收目录，一篇一个子目录，文件名带文章短名与图序；过目以脚本 stdout 报出的文件名为准，stdout 不完整就先列验收目录再读图，不按 fig1、img2 的想当然命名去猜。截图前先数一数文章里的图块数，脚本报 0 块而文章里有图，说明页面加载错了（路径打错、服务未起、404），不是文章没图——错误页上的「成功」退出码不作数，先核对路径与服务再重截。

图出了问题先分归属再动手：图内容画错、结构难看、标签超宽，改文章里的图；样式裁切、字号过小、错位、主题不适配，改渲染端的站点代码。两边都改了就重新截图确认，改完不重截等于没改。

配图前检查插图位置周围的标题、普通文字、列表、表格和代码，保留它们的语义结构。配图验收同时查看含前后文字的文章页面截图：图内标签可读、相邻文字字号一致、表格列边界一致、手机横向滚动限于表格容器。图块局部截图只能证明图块本身；发现共用排版问题时交由 `站点开发技能` 修复，并运行站点脚本目录下的 `note_verify_shots.py --base <本地验证实例地址> --path <文章路径>`（本地验证实例的地址与启动方式见 `站点开发技能/SKILL.md` 的环境表，各站点不同）。配图检查与文章排版检查分别报告结果。

## 数量与节奏

讲做法、讲机制的文章通常图文相间，查条目用的参考手册一般不配图，实测样本见 `references/benchmarks.md`（样本取自技术媒体与技术文档，换领域先找同类样本再定密度）。讲结构、讲流程、给数据的小节值得配图，讲背景、讲结论、列参考文献的小节不必。节奏看阅读体验：图全挤在开头或结尾、连着多屏纯文字没有视觉停顿，都说明节奏不对。

条数另有下限，密度只当筛子：正文 ≥2000 字至少 2 张、≥4000 字至少 3 张、<2000 字 1 张够用。
实测（2026-09-25，452 篇）：按密度判据，219 篇「只有 1 张图」全部达标，读者的第一反应却是图太少——
三千字全程只有一处视觉落点，数字合规，读起来仍是长文无图。密度是比例，读者感受到的是「多久遇到一张」，
两者不是同一件事。另一条独立判据：正文里完全没有指代图的句子（没有「图」「上图」「这张图」），
即使条数达标也判未接住。凑数用的复述型图不算数，该省略就省略并留待办。
条数下限只在找得到主题对位图时追：找不到就不加，为凑下限塞进无关的图（生活比喻图在内）比条数不足更糟。

## 收尾核对

逐张过一遍，四个问题，任何一条不过就改或删：

1. 删掉这张图，文章损失信息吗？不损失就删。
2. 图只回答一个问题吗？标签跳过正文能看懂吗？
3. 文字已经说清楚、图只是重复文字的情况有吗？有就删。
4. 外链图写明来源了吗？地址是 https 吗？

## 脚本

脚本只做检查与批量信息读取，不参与产出；按需取用，不要为每张图安排例行检查。

| 脚本 | 作用 |
| --- | --- |
| `scripts/audit_mermaid.py` | 渲染量图宽与手机端字号，拿不准时兜底；`--mermaid-js` 指定 mermaid.min.js |
| `scripts/audit_bitmap.py` | 复查文章里已写入的图片引用 |

## 改本技能之前

改 SKILL.md 或 references 之前先读 `skill-craft/SKILL.md`（与 design-craft 等并列于 skills 根目录）。新结论要不要写入、怎么把个案抽象成通用判据、怎么用模型验证产出并反推漏项，都在那里。同一份规程不放第二份。

改完派别的模型来攻：指令写明"先证明产物是错的"，没指出具体问题的通过不算通过。身份可并行——下游使用者（按改后流程真配一次图，指出卡在哪一步）、挑剔审计员（指定 MECE、SWOT、五问之一扫一遍）、反向追问（让模型就难点对自己连环提问，人来回答）。只报能让产物出错的具体输入。

三条纪律：**能配上图不等于配得对**——图渲染出来只说明没坏，要回答"这张图帮读者多懂了什么"，答不上就是占位；**自己先拿到事实**——文章主题、已有图源、实测效果是自己的 1 和 2；**再进一步**——这次找图踩的坑能不能变成一条图源判据。
