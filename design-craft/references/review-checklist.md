# 交付前自检

入口：改完界面，交付之前逐项过；或者觉得"哪里不对但说不清"时按这个顺序查。

## 第一遍：层级与可读性

- [ ] 一屏内层级不超过四档，且字号/字重/颜色三个旋钮都动了
- [ ] 正文对比度 ≥ 4.5:1，深浅两个主题都验过
- [ ] 正文行宽 ≤ 760px，行高在 1.6–1.75
- [ ] 逐元素核对 `p/li/blockquote/th/td/code`，普通文字、列表、引用和表格同字号且 ≥ 16px；行内代码继承字号，代码块 ≥ 16px
- [ ] 主标题规则限定头部，小节标题按自身层级显示；核对媒体查询后的 computed style
- [ ] 表头与每行单元格的左右边界误差 ≤ 1px；表格保留原生分组布局，多列表格可在自身容器内滚动到最后一列
- [ ] 真实文章样本覆盖两列与多列表格、长英文、代码、引用和列表；检查站点提供的 `$KNOWLEDGE_REPO/scripts/note_verify_shots.py` 存在后执行其 --base <验证地址> 参数，查看 JSON 与表格局部截图

## 第二遍：布局与密度

- [ ] 间距值全部落在 2/4/8/12/16/24/32/48/64 上
- [ ] 页面底 / 内容区底 / 卡片底三级拉开，卡片能"浮起一档"
- [ ] 删掉的区块有补位，没有空洞；没有整条空着的右栏
- [ ] 同一纵向流里的区块宽度只有一个真源：正文、收尾卡、图谱区宽度差 ≤ 2px；隐藏态元素（未触发的提示卡）不占位
- [ ] 375 / 768 / 1024 / 1440 四种宽度分别截图，页面整体没有横向溢出；宽表格和代码块在自身容器内滚动，末端内容可完整查看
- [ ] 上面这条的表格部分依赖站点侧样式，不是文章能自证的项目。本站 CSS 目前只对导航做过容器滚动，正文表格没有任何 `overflow` 规则，390px 下多列表格会撑到 481-641px（实测十篇里五篇如此）。按本条验收前先确认站点是否已加表格容器滚动，没加就是站点改动，不是文章问题，也不要因为这条做不到就把多列表格改成列表。
- [ ] 固定导航没有盖住内容
- [ ] 内容没有顶格贴着固定导航下缘，标题/正文与固定栏之间有呼吸（≥16px，有全站头部规范按规范值）
- [ ] 图表内标签/名牌不压相邻图形元素；右下角常驻元素（功能钮与功能指示）形态可区分、互不撞车
- [ ] 每个区块的可点元素 ≤ 3 个，且主操作只有一个；同形按钮不并排（同形即同权重）
- [ ] 按钮之间无包含关系：没有两个按钮指向同一份目标、同一个 URL 的两种说法
- [ ] 全站 grep 链接目标：同一 target 的入口只留一处；总览页放完整一套，详情页只留主操作
- [ ] 没有与总览页结构、卡片、按钮雷同的第二页面
- [ ] 所有可点元素逐个真点一次：JS 改写的 href 喂边界输入验产物，带 `#锚点` 的核对目标页存在同名 id
- [ ] 中英两个语言各截一遍整页：动态拼接串（数字混排）不残留另一语言；定宽容器里的恒定文本两种语言都完整不截断（`scrollWidth <= clientWidth` 量）
- [ ] 共享壳层的移动端机制（折叠、汉堡按钮）逐页验证初始态与点击行为；新接的 companion 页移动端单独截一遍

## 第三遍：状态与交互

- [ ] 所有可点元素：hover 反馈 + `cursor: pointer` + focus 可见
- [ ] 图标按钮/裸符号按钮有真实可访问名称：`aria-label`（或可见文字）必须是读屏能念的中文词，不许拿 `＋`/`－`/`×` 符号本身当名称，也不许只靠 `title` 兜底（可见文本优先于 title，读屏念出来仍是符号）；同一站点同类控件一套标准（实测：图谱工具栏有 aria-label、mermaid 图控件没有）
- [ ] 状态会变的控件（折叠、开关、切换），可访问名称随状态重算：名称与状态（含语言）的同步收敛到一个函数，状态变化与语言切换两个事件都调它；名称是拼接串时按语言分支拼装，不依赖词典整串命中
- [ ] 键盘到达正文 ≤ 2 步（Tab 步进实测，不是目测）；有 skip link 时回车后焦点真的落进目标容器（目标 `tabindex="-1"`）
- [ ] 视图切换后焦点有归还：会触发自身隐藏的按钮（返回、关闭、收起），每个分支终点聚焦到对应入口（列表项/品牌链接/搜索框），不许焦点摔到 body 从头走 Tab
- [ ] `aria-current` 取值按语义分档：整页路由导航用 `page`，滚动驱动的位置标注（scrollspy、目录）用 `location`；样式选择器跟着实际取值写，两档不混用
- [ ] 关掉 outline 的元素必须有等价替代：聚焦后量三样——可见焦点标记、悬停反馈的键盘等价物（`focusin/focusout`，不许 `onmouseenter` 独占）、状态属性与可聚焦性匹配；缺一即净失去
- [ ] 渲染函数重建 DOM 的路径上，核对每个交互临时状态（缩放/平移/展开/勾选）的回放点：全局 state 里存了什么，重建后 DOM 就该是什么，工具栏数值与画布不许分家
- [ ] 组件级显隐按渲染态类名写（JS 渲染时切换 `is-*` 容器类），不按视口宽媒体查询猜渲染模式；同一规则存在 `:has()` 版与媒体查询"兜底"版时，先量两者边界是否一致
- [ ] 每个视图的当前态恰好标记一个元素：全站统一用 `aria-current` 载体，赋值收在渲染入口（不在一次性闭包里），`[aria-current]` 样式必有对应赋值点
- [ ] "hover 无反馈"先查语义再定性：当前位置项、静态卡有意静默的不算翻车
- [ ] 当前态与推荐态视觉可区分，且语义没被数据驱动
- [ ] 动效 ≤ 300ms，有 `prefers-reduced-motion`
- [ ] 加载/空/错误三态都有内容，不是白屏
- [ ] **滚动与位置对标成熟站**：下滚按**方向**收起搜索框与头部、上滚复现（按距离会抖动）；长文下滑吸顶显示标题不遮首行；返回列表保留位置，筛选排序不跳顶，锚点留 `scroll-margin-top`
- [ ] **阅读与加载**：阈值后回到顶部；长文有进度；加载更多/无限滚动与 URL、历史返回协调；图片懒加载且预留宽高比；切主题不闪白
- [ ] **弹层与搜索建议**：Esc 关闭、焦点锁层内、开时锁 `body` 滚动；建议列是 `combobox`，↑↓ 选、Enter 确认、Esc 关闭
- [ ] **导航与状态可分享**：面包屑反映真实层级且每层可点回上层；筛选、排序、Tab 状态写进 URL，刷新与分享链接后仍保持（不写 URL 的状态，用户一刷新就丢）
- [ ] **移动端手势与按钮一一对应**：左右滑动切 Tab/返回、下拉刷新要有等价按钮；只做手势不做按钮，桌面与键盘用户拿不到同一能力

## 第四遍：文案

- [ ] 没有讲"过程/口径/统计方法"的说明段
- [ ] 没有英文装饰小字、重复标题
- [ ] 通读一遍，没有幼稚表达

## 第五遍：实证

- [ ] 截图（不是看代码），深浅两个主题各一张；带透明度的亮色装饰层（光晕、水洗底、玻璃卡）两个主题都要单独看过，深色下不得比页面底色亮出一档
- [ ] 关键交互走一遍真实路径（点进去、返回、刷新、深链）
- [ ] 换了数据/换了宽度再验一次，第一遍过了不算过
- [ ] **测量工具先过对照实验再产出证据**：无头浏览器等工具可能在容器里整体失灵（实测：Chromium 148 与 Firefox 150 在容器内 Tab 顺序导航全部失效，连三链接静态页都走不动，键盘注入 keydown/insert_text 均无效），用键盘走查当证据前，先拿一个只有两三个链接的最小静态页验工具本身能否走通；工具坏了时改用环境无关的 DOM 序审计（可聚焦元素按 DOM 序 dump、可访问名称遍历），并作废此前同源证据，空追现象成本极高
- [ ] **可聚焦元素 dump 必须过滤真实可见性**：`querySelectorAll('button,[tabindex]')` 会数进 `display:none` 容器里的元素（实测：清单态下隐藏的缩放工具栏 4 个按钮混进 Tab 序 dump），不过滤就高估序列、掩盖真空缺；先按 `offsetParent`/`getBoundingClientRect` 过滤，或直接真键盘 Tab 步进记录落点
- [ ] **触摸手势验证用 CDP 真实触摸注入，合成 PointerEvent 会假阴性**：手势处理函数调 `setPointerCapture` 时，脚本合成的 PointerEvent 因假 pointerId 抛错被吞，表现为"手势无效"——那是测试手法坏了，站点没问题（实测：合成事件捏合无反应，CDP `Input.dispatchTouchEvent` 同一场景 1.00→2.00 生效）；断言看 state 数值变化，不看有没有报错

## 常见翻车（本项目都发生过）

| 现象 | 真因 |
|---|---|
| 深色模式刺眼 | 硬编码色值，没走 token |
| 导航不知道自己在哪 | 当前态样式被挪去做别的事 |
| 页面看着空 | 元素删了没补位，只删不排 |
| 同一件事两个数字 | 两个页面统计口径不同却都写出来 |
| 高亮没人点 | 颜色对但位置埋没，或位置对但太刺眼 |
| 脚本全绿但页面难看 | 压缩类指标只设了上限，把呼吸压没（标题顶格贴顶栏）；趋零值也是违规 |
| 深色首页顶上一条亮带 | 浅色调好的半透明光晕直接用在深色；装饰层必须两主题分别截图核对 |
| 停留越久越卡、流量翻倍 | 渲染函数每次重建都重新取数；取数要有缓存挡门，轮询先比签名（细则见 `states-motion.md` 性能节） |
| 右下角两个"？按钮" | 功能动作（提意见 FAB）与功能指示（快捷键提示）做成同款胶囊同位常驻；指示类用键帽形态 |
| 英文站名截成「Engineering K…」 | 品牌字号按中文量定，英文同字号长两到三倍；EN 态降档字号换完整显示 |
| 英文页面残留中文「约 4 分钟」 | 数字拼进句子的串词典整串不命中；渲染处按语言分支拼装，不指望 translateDOM |
| 四个 companion 页移动端侧栏永不折叠、正文起点 499px | 折叠机制做成壳层 opt-in 且只在首页传参；改为壳层默认开（opt-out），展示规则收进全局样式 |
| 键盘到正文要很多步 / 跳转后焦点弹回 | 侧栏写在 `main` 之前，Tab 按文档序走；skip link 放 `<body>` 开头且目标容器加 `tabindex="-1"`（细则见 `states-motion.md`） |
| Tab 键序走查结果自相矛盾（skip link 时而第一时而第 12 位） | 无头浏览器在容器里 Tab 顺序导航整体失效，走查数据是幻觉；先拿最小静态页验工具，工具坏了改用 DOM 序审计 |
| 图标按钮读屏只念符号 | `＋`/`－` 按钮没写 aria-label，可见符号被当成可访问名称；同站点同类控件（图谱工具栏）有名称，两套标准 |
| 收起后读屏仍念"折叠" | 状态会变的控件只在渲染时赋一次 aria-label；名称必须随状态重算，重算逻辑收敛成一个函数，状态与语言两个事件都调它 |
| 切英文后读屏听到中文动作词 | 可访问名称是 `${动词}${名词}` 拼接串，词典按整串匹配永不命中；按语言分支拼装，两段各自走词典 |
| 读屏把目录当前节当页面切换 | 滚动驱动的位置标注用了 `aria-current="page"`（读屏把 page 当导航 landmark 快捷键目标）；位置语义用 `location`，整页路由才用 `page` |
| 449 个图谱节点键盘聚焦零反馈 | `.node:focus{outline:none}` 只关不给；悬停探索反馈独占 `onmouseenter` 键盘不存在。关焦点环必须同时给等价替代，悬停与聚焦共用同一函数 |
| 缩放显示 229%、图形实际 100% | 渲染函数整体重建 SVG 但不回放全局 state 里的缩放/平移，控件与画布分家；重建路径末尾统一回放临时状态 |
| 621-760px 容器力图态手势指引整行消失 | 显隐规则用视口宽媒体查询冒充渲染模式判定，边界（760px）与真实模式边界（容器宽 620 + 聚焦分支）不一致；改由 JS 渲染时写 `is-list` 容器类，CSS 消费类名 |
| 返回列表后焦点摔到 body | 隐藏触发链路的按钮（工具组 hidden）没在分支终点归还焦点；每个分支都要聚焦到对应的列表入口 |
| 当前态停在旧页面上、读屏漏报 | 赋值写在增强闭包里只跑一次，路由切换后不刷新；赋值统一收进渲染入口，且全站只用 aria-current 一个载体 |
| 按钮平铺分不出主次 | 同形按钮即同权重；次要与外链降为文字链，按钮形态只留主操作。同一入口只在一个页面长出来。 |
| 按钮点了落到错误目标 | href 由 JS 改写，脚本未跑到该分支时保持 HTML 初始值；空输入提交落到空参数确认页。每个入口喂边界输入实测产物 |
| 锚点链接静默跳到页顶 | `/page#id` 的 id 在目标页重构后消失，不报错只是跳顶部；全站锚点逐个核对目标页存在同名 id |
| 写了当前态样式但从不生效 | `[aria-current]` 选择器全站没有赋值点，失效样式；先 grep 赋值点再判断 |
