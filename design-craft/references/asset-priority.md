# 核心资产定位与优化顺序

入口：开始任何美化、审计、改版任务之前读；做到一半发现"哪里都想改、不知道先改哪"时也读。

## 一、为什么要有这一步

界面优化最容易犯的错误：从最容易看到的界面开始改（首页、导航、着陆页），因为它们最常被截图、最容易出"改了"的成就感。访客却是因为另一个目的来的，那个目的对应一个具体界面。周边界面改得再精致，访客在核心界面读不下去，任务就是失败的。

所以任何美化任务的起点是回答：**这个站点靠什么界面产生价值？**

## 二、定位方法

按顺序问三个问题，答案落在具体界面上：

1. **访客为什么来？** 他带着什么任务打开站点（读一篇文章、买一件商品、完成一次操作、查一条数据）？这个任务在哪个界面完成？
2. **哪个界面失败最伤？** 关掉站点的那一下发生在哪个界面？通常是：内容读完的页面、下单按钮所在的页面、主操作画布。
3. **哪个界面占访客时间最长？** 停留时间最长的界面就是价值兑现的地方。

三个问题通常指向同一个界面。指向不同时，以问题 1 为准（目的决定价值），拿不准就问用户，用户的评价优先于推断。

## 三、排序规则

定位到核心资产后，三条规则安排所有工作：

- **空间规则**：核心资产占版面主体。辅助模块（导航、图谱、推荐位、相关内容、统计角标）放主内容之后、两侧栏、或折叠区。首屏属于核心资产，辅助模块不许把它挤出第一屏。
- **顺序规则**：优化从核心资产开始，做到能拿出手，再轮到周边界面。对周边界面产生的任何改进冲动，先记下来，不许插队执行。
改完后重跑同一脚本确认违规清零——只跑此前违规的页面加每个领域一篇代表页，不重扫全量，也不另写新脚本（换了脚本测法就变，数字没有可比性），再补拍代表页确认视觉。**压缩类指标必须同时设上下限**：正文起点、辅助区高度这类"越小越好"的指标只设上限，会把呼吸空间一并压没（本项目实测：正文起点一路压到标题顶格贴着固定顶栏，脚本全绿，页面难看）。每个被压缩的指标都问一句"压到零会怎样"，趋零的值与超限的值同样算违规。

## 四、常见误判

| 误判 | 实情 |
|---|---|
| 首页最重要 | 首页是门厅，访客从门厅路过，真正待着的是内容页或操作页 |
| 图谱、统计、面板最出彩所以先改 | 出彩的周边模块挤占首屏 = 用配菜挤掉主菜 |
| 壳子（导航、页脚、按钮）改起来快先做壳 | 壳子服务于内容，内容不能读时壳子没有意义 |
| 每个页面平等对待、每页都改一点 | 精力摊平 = 核心资产没被做到能拿出手 |

## 五、例子（仅为例子，判断以访客目的为准）

- 知识库 / 博客 / 文档站：核心资产是**文章页**（正文排版、字号行高行宽、目录、阅读连贯性）。图谱、推荐、同模块、统计都是配角。
- 电商：核心资产是**商品详情页与下单链路**。
- 工具 / 编辑器类：核心资产是**主操作画布**。
- 仪表盘：核心资产是**关键指标的可读呈现**。
