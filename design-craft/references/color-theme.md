# 配色、token 与深浅主题

入口：动颜色、加语义色、做深色模式时读。

## token 是唯一真源

- 所有颜色走 CSS 变量，禁止在组件里写死 hex（frontend-design 明令禁止；本项目实测：140 处硬编码色值是深色模式反复坏掉的根源）。
- 语义命名，不按色相命名：`--color-accent-soft`（底）/ `-line`（边）/ `-ink`（字）/ `--color-accent`（强调条或图标）。一套语义四件套，深浅主题各自给值。
- 深浅主题**共用**字号/间距/圆角 token，只换颜色（TDesign M03）。

## 对比度

- 正文 ≥ 4.5:1，大字 ≥ 3:1（ui-ux-pro-max `Color Contrast`）。
- 语义色四件套的分工是硬约束：`-ink` 是文字专用档，base 档只给填充与大面积（圆点、进度条、按钮底）；base 档用在正文链接、步骤号、按钮文字上是高发违规（实测：绿 base 在白底 3.58:1，浅底浅字目测舒服、截图看不出，WCAG 数值扫描才现形）。验收必须逐元素数值化扫亮暗两主题，两边都过线。
- 浅色底正文用最深档文字，禁用灰字压灰底；muted 文字至少到中灰档（同库 `Muted text light`）。
- 边框在两个主题下都要可见；浅色模式别用 `rgba(255,255,255,.1)` 当边框，等于没有。
- 玻璃/半透明卡片在浅色模式下不透明度要够（≥ 0.8），否则内容发虚（同库 `Glass card light mode`）。

## 深色模式的四个坑（本项目都踩过）

1. 写死白描边：浅色下干净，深色下刺眼 → SVG 与描边一律 `currentColor` 或 token。
2. 只换背景不换语义：文字档位没跟着切，出现"深底深字"。
3. 阴影在深色下无效 → 深色靠底色差与描边分层级，不靠阴影。
4. 半透明亮色装饰直接搬：浅色下 13% 的亮蓝光晕在深底上成为一条发亮横带（实测：同一套 `color-mix` 透明度叠在深底，比页面底色亮一档，像渲染错误）。凡带透明度的亮色装饰层，深色下必须换深色专用 token 重调强度，深浅两主题都截图核对，不能只在浅色下调好就交付。

## 用色的量

- 主色 + 1 个强调色足够，全站颜色 3–5 个（frontend-design：过多颜色是禁止项）。
- 颜色只用于**语义**：成功/警告/错误/推荐/当前位置。装饰性用色要有明确意图。
- 不靠颜色单独表达状态：配图标或文字（红绿之外必须有第二信号）。

## 渐变与背景

- 渐变、噪点、网格背景是加分项，但只能有一处主角，别整页铺（frontend-design 背景章）。
- 纯色背景不是错：内容型页面纯底 + 一处纹理比满屏渐变更耐看。
