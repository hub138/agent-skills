# OpenAI agent 工作流评测：追踪、评分器与数据集

- 来源：OpenAI 官方文档（镜像站 html 抓取，正文抽取后按本包语言规则改写）
- 发布：官方文档页，随平台持续更新
- 译文说明：原文为英文（镜像站自带中文翻译，对照官方原始 URL 收编），两页合并成一篇：agent-evals 是评测面选型决策页，trace-grading 是追踪评分操作页。环境事实：OpenAI 已宣布 Evals 平台退役，存量内容在过渡期可用，2026-10-31 对既有用户转只读，2026-11-30 计划关闭；traces 与 trace grading 评测面不受退役影响，是持续存在的入口。

OpenAI 平台给 agent 工作流提供一套评测工具：追踪、评分器、数据集、评估运行。官方把 agent-evals 页定位为「选择对 agent 工作流最关键的评测面」的决策点，核心是一条先后路径：还在调试行为时先从追踪开始，需要可重复性时再转向数据集与评估运行。

## 决策路径：先追踪，后数据集

### 还在调试行为时，先从追踪开始

追踪评分是识别工作流层面问题最快的方法。一条追踪捕获单次运行的端到端记录：模型调用、工具调用、护栏、handoff 全在内。评分器让你用结构化标准给这些追踪打分，从而大规模发现回归与失败模式。

官方列了四个典型问题，都是追踪评分的适用场景：

- agent 是否选了正确的工具？
- handoff 是否在应当发生时发生了？
- 工作流是否违反了指令或安全政策？
- 提示词或路由的改动是否改善了端到端行为？

### 追踪评分工作流

1. 打开仪表盘的 Logs > Traces。
2. 检查一条有代表性的工作流追踪（来自 SDK 应用的追踪，或过渡期内来自现有 Agent Builder 工作流的追踪）。
3. 创建一个评分器，对选中的追踪运行它。
4. 用结果优化提示词、工具面、路由逻辑或护栏。

代码优先的 SDK 工作流，正式建评分器之前先从集成与可观测性入手，拿到高信号追踪。

### 需要可重复性时，转向数据集与评估运行

一旦明确「什么是好的」，就从单条追踪转向可重复的数据集与评估运行。对改动做基准测试、对比不同提示词、随时间做更大规模评估，走这一步。需要针对外部模型的评估、评估 API 或更大规模批量评估这类高级功能时，把 Evals 与数据集一起用。

## 追踪评分的定义

追踪评分：对 agent 的追踪分配结构化分数或标签，评估正确性、质量或符合预期的程度。追踪是决策、工具调用与推理步骤的端到端日志。这些标注帮助识别 agent 在哪些方面表现好、在哪些地方犯错，从而对编排或行为做有针对性的改进。

追踪评估：用这些已评分的追踪，跨多个示例系统性评估 agent 表现，帮助做变更基准测试、识别退化、验证改进。与黑盒评估的差别：追踪评估提供更多数据，能更好理解 agent 为什么成功或失败。

两个功能配合使用：追踪评分做标注，追踪评估做规模化分析，一起跟踪、分析、优化 agent 群组的性能。

## 追踪评分的操作步骤

### 开始使用追踪

1. 仪表盘导航到 Logs > Traces。
2. 选择一个工作流。能看到来自 SDK 应用的追踪与过渡期内 Agent Builder 工作流的追踪。
3. 选择一条追踪检查工作流。
4. 创建评分器并运行，按评分器标准给 agent 表现打分。

追踪评分是大规模识别错误的有价值工具，这对在 AI 应用里构建韧性至关重要。

### 通过运行评估追踪

1. 选择 Grade all，进入评估仪表盘。
2. 在评估仪表盘里添加与编辑测试标准。
3. 添加一个运行评估输出。可配置运行选项：模型、日期范围、工具调用，取得更具体的评估结果。

## 与包内既有篇目的关系

Anthropic 侧的 agent 评测总纲见[为 AI agent 解密评估](evals-demystified.md)（八概念定义：task、trial、grader、transcript、outcome、评估 harness、agent harness、评估套件，pass@k 与 pass^k 的选型）；通用评估设计原则（评估器三类、四层架构各自的评估点、LLM 裁判的位置与长度倾向）见[OpenAI 评估最佳实践](openai-eval-best-practices.md)；Claude Code plugin 级评测的实施方法（case 与 grader 文件布局、六类 grader、双臂对比、CI 门禁）见[Claude Code plugin evals](claude-plugin-evals.md)。本篇补的是 OpenAI 平台侧的追踪评分入口：追踪捕获什么、评分器怎么建、什么时候从单条追踪升级到数据集。

transcript 与 trace 在两家机构是同一件事的两个名字：Anthropic 叫 transcript（完整 messages 数组），OpenAI 叫 trace（端到端日志），都是多轮 agent 评测区别于单轮 prompt 评测的关键载体——只看最终回答会掩盖流程缺陷，读完整轨迹才能定位到具体哪一轮选错工具、哪个参数填错。
