# OpenAI Agents SDK：代码优先的智能体构建

- 原文：[Agents SDK](https://developers.openai.com/api/docs/guides/agents)
- 来源：OpenAI 官方 API 文档（镜像站 developers.openai.ac.cn 抓取，官方站对命令行抓取返回 Forbidden）
- 发布：官方文档页，随 OpenAI 平台持续更新
- 译文说明：原文为中文镜像，本篇为按本包语言规则的合规改写整理，术语保留英文原词。

智能体是能够进行规划、调用工具、在不同专属智能体之间协作并保留足够状态以完成多步骤工作的应用程序。用 OpenAI Agents SDK 通过代码构建智能体，并按需要扩展到更高级的运行时模式。

## 运行第一个智能体

从 Agents SDK 快速入门开始：安装 SDK，定义一个智能体，运行它。一切正常后，返回此页选择应用程序需要的下一个能力。

更多示例、问题反馈与特定语言的参考详情在 GitHub 仓库：TypeScript SDK 与 Python SDK 各一个仓库。

## 选择起点

按「想做什么」选入口页，每个入口对应 SDK 的一块能力：

| 想做什么 | 入口 | 说明 |
|---|---|---|
| 构建代码优先的智能体应用 | 快速入门 | 实现可运行的 SDK 集成的最快路径 |
| 清晰定义一个专属智能体 | Agent 定义 | 还在确定单个智能体的接口规范时从这里开始 |
| 选择模型、默认值与传输方式 | 模型与服务商 | 模型选择、服务商设置或传输策略影响工作流时用 |
| 理解运行时循环和状态 | 运行 Agent | 智能体循环、流式输出、持续运行策略 |
| 在基于容器的环境中运行工作 | 沙箱 Agent | 智能体需要文件、命令、软件包、快照、挂载或服务商链接时用 |
| 设计专属智能体归属 | 编排与交接 | 需要多个智能体且必须决定谁负责回复时用 |
| 添加验证或人工复审 | 护栏与人工审核 | 工作流在继续高风险工作前应该阻塞或暂停时用 |
| 了解运行返回的内容 | 结果与状态 | 最终输出、可恢复状态、下一轮交互界面 |
| 添加托管工具、函数工具或 MCP | 使用工具、集成与可观测性 | 工具语义在平台工具文档；SDK 侧的 MCP 与追踪在这里 |
| 检查并优化运行效果 | 集成与可观测性、评估智能体工作流 | 先用追踪调试，再进入评估循环 |
| 构建语音优先的工作流 | 语音 Agent | SDK 的语音管道与实时智能体模式 |

## 使用 SDK 进行构建

服务器负责部署、工具实现、状态存储与审批决策，SDK 负责运行智能体循环并调用这些工具，这是 SDK 方案的分工形态。适合以下需要：

- 用 TypeScript 或 Python 编写的类型安全的应用代码
- 对工具、MCP 服务器和运行时行为的直接控制
- 自定义存储或服务器托管的对话策略
- 与既有产品逻辑或基础设施紧密集成

推荐的 SDK 文档阅读顺序：

1. 从快速入门开始，先在屏幕上实现一次成功的运行。
2. 用 Agent 定义与模型与服务商把一个专属智能体定义清楚。
3. 工作流变复杂后，继续读运行 Agent、编排与交接、护栏与人工审核。
4. 应用逻辑依赖运行（run）对象或需要更深入了解行为时，读结果与状态、集成与可观测性。

## Agents SDK 对比 Responses API

想自己掌握循环，用 Responses API；想让 SDK 运行循环，用 Agents SDK。

选 Responses API 的情形：无论工作流需要一次调用还是多次调用，都希望直接控制模型交互、输出项、工具、状态与编排；希望在应用程序里直接实现自定义工具路由、循环或分支。Responses 的函数调用流程里，应用程序接收函数调用、执行它们、返回输出、再次调用模型。例如一个 Responses 工作流搜索知识库并生成带引用的回答。

选 Agents SDK 的情形：希望 SDK 管理智能体循环与反复出现的编排（重复的工具调用、分支）；不同专属智能体需要不同的指令、工具或策略；需要内置的会话、追踪、护栏或可恢复的审批流。Agents SDK 的运行器（runner）执行工具循环，在交接后切换智能体，在运行结束或因等待审批而暂停时停止。例如一个 Agents SDK 工作流调查支持请求，交接给正确的专属智能体，调用内部系统，请求退款审批，记录结果。

两个选项逐项对照：

| 维度 | Responses API | Agents SDK |
|---|---|---|
| 最适用于 | 自定义模型驱动的功能与工作流 | 有定义好的工具与反复出现编排模式的有界对话或交易工作流 |
| 核心抽象 | 模型响应 | 智能体运行（run） |
| 工具 | 平台工具、函数调用、远程 MCP | 连接到可重用智能体的平台工具，加工具包装器、本地 MCP 连接、智能体即工具 |
| 工作流编排 | 自行管理自定义循环与分支 | SDK 提供智能体循环与生命周期 |
| 多智能体工作流 | 自行构建路由与委派 | 内置智能体即工具（agents-as-tools）与交接（handoffs） |
| 状态 | 手动管理历史、响应链或 Conversations | 相同选项，加 SDK 会话与可恢复运行状态 |
| 安全与审批 | 特定于工具的审批；更广的控制自己构建 | 输入、输出与工具护栏，加可恢复审批流 |
| 调试与追踪 | 响应对象与 API 日志 | 跨模型调用、工具、智能体、护栏、交接的内置追踪 |
