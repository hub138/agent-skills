# Skill 自进化：执行轨迹 + 评测反馈的多代优化（GEPA-style）

来源：20261115-8bfbcdcd59a6fa3d.md（含完整候选池设计/入池规则/支配判定公式）

## 机制
黄金评测集 + 执行轨迹 → 反思提出候选（归因变异提示词）→ 全量评测 →
父子逐 Case 支配判定（严格支配不入池/互不支配入池）→ 全局候选池动态选优
（活动前沿贪心覆盖）→ 多代迭代。全程记录变异/父子关系/判定原因。

## 对照 agent-ops：这套机制可以直接映射
| 自进化环 | agent-ops 已有资产 |
|---|---|
| 黄金评测集 | pytest 97 项（行为契约即评测） |
| 执行轨迹 | task_events + decisions.jsonl + FIELD-NOTES |
| 候选池 | git 提交历史（每个候选可回滚） |
| 支配判定 | 缺——需要逐行为维度的评测打分 |

## 判定：adapt（本期不落地，方案留档）
可落地方案：把 SKILL.md 的演进做成「测试驱动的迭代环」——
变异候选 = SKILL.md 的 diff（改触发词/加流程），评测 = pytest + doccheck +
真实任务 transcript 抽查，支配判定 = 按维度（触发命中/门禁通过/任务成功率）逐项比较。
工程量数天（评测维度定义 + 轨迹关联）。触发条件：SKILL.md 手改频率足够高
（每月 ≥3 次实质性变更）时才值得自动化，当前手改频率低，人工审阅更划算。
