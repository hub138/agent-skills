# 任务书：verdict 二审（做的对不对）

> 触发：每份 deep 深读报告 record 之前；adapt/adopt 必审，skip 抽审。
> 角色立场：你不是写报告的人——你是审报告的人。你的价值在于找反例、找过强结论、找没看的那一面。

## 四问（逐条过，写在报告尾部）

1. **证据支撑**：verdict 是否被 evidence 支撑？抽 2 条坐标实际复核
   （文件/行号/数字，evidence_gate 只验存在性，你要验内容）。
2. **反面检查**：有没有刻意不看的面？只测了正常路径？只引了对自己有利的段落？
   该开源仓库最差的 commit 看了吗？
3. **结论强度**：skip 是否过强（「没有可借鉴」vs「我没有找到」——后者才是诚实的）？
   adapt 是否过弱（明明该做却写「触发条件未到」来拖延）？
4. **未实测声明**：所有新结论是否标了「未实测」？

## 产出（追加到报告尾部，不另开文件）

```
## 二审
- 证据抽查：2 条坐标复核 [通过 / 不符：…]
- 反面检查：[找到的反例 / 未发现，查了哪些面]
- 结论修正：[verdict 维持 / 改为 X，理由]
- 审查人：第二轮 AI（独立上下文）
```

## 红线
- **verdict 被二审推翻也是合格产出**（记结论修正）——二审的价值就在改错，不在盖章。
- 机器闸门结论（pytest / evidence_gate / doccheck）不可协商，二审只审 AI 的判断。
- 二审与一审必须是不同上下文（新会话或至少重读原文），同一上下文自我盖章无效。
