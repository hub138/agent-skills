# agent-ops 通用研究迭代 Loop 实施方案

> 日期：2026-11-20。性质：设计与实施任务书，不是已实现能力说明。
> 本次只交付这一份方案；不启动 Loop、不修改现有运行脚本、不发送通知、不提交或发布。
> 给后续实现模型：按第 12 节分步实施，每步拿真实验收证据；不以代码行数、生成报告字数或任务退出码判定完成。

## 1. 目标与现状：不是堆脚本，是把探索变成可验证的改进

目标：在 agent-ops 中增加一套通用、可恢复、可复盘的研究优化流程。研究者给目标、材料、评测方法和探索策略，系统持续提出假设、运行实验、比较效果、保留有效改动，输出清晰的阶段汇报。

适用例子：缺陷审查、提示词优化、规则生产、性能调优、测试生成、检索策略、算法或工具方案对比。核心不认识 tbase、repomind、Joern 或 Semgrep；领域能力通过适配器接入。

“任何研究都能接入”有边界：必须能定义输入、候选产物、验证方法和证据。没有客观评测的开放调研也可登记、探索、归档，但不能自动声称性能提升或达到质量目标。商业工具没有授权时记录 blocked，不自动购买或绕过授权。

### 1.1 已有的底盘，继续用

| 已有能力 | 当前位置 | 本方案如何复用 |
|---|---|---|
| 排队、租约、重试、任务组 | scripts/taskctl.py、scripts/task_group.py | 派发实验子任务、关联任务组，不再造第二套进程队列 |
| 会话派发、续接、定位 | scripts/agentctl.py | 支持人工或交互式运行；主模式仍用 taskctl，不重复派同一实验 |
| 方向指导、监督、恢复 | scripts/manager.py、两个 supervise 后端 | 监督执行停滞；不能越过实验门禁批准候选 |
| 来源分诊、只读调研、借鉴台账 | scripts/radar_*.py、radar/ | 来源接入候选，不把“值得读”直接当“值得部署” |
| CLI 探测、模型策略、失败识别 | platform_util.py、model_policy.py、provider_events.py | 沿用唯一权威源，不另复制模型名单和硬编码路径 |
| 任务进度与结果契约 | progress.md、result.json、任务模板 | 作为执行结果；实验有效性另作严格检查 |
| 技能开发规范 | GOVERNANCE.md、ANATOMY.md、CHANGELOG.md | 新功能纳入同一套维护和回归规则 |

已核对的不足：缺少统一实验账本、冻结评测协议、独立验证、候选晋级与回退、训练和留出隔离、研究方向与实际收益的关联。现在 taskctl 的 done 可能只是进程正常结束，证据检查还有警告不阻断分支，不能直接作为研究成功的证明。

环境检测也不能照旧宣称绝不会误判：现有 env_check.py 有“codebuddy 路径存在就改为 ok”的分支，knot 也主要检查路径；它证明不了模型可用。要分开验证 installed、version_ok、authenticated、smoke_ok，安装和真实请求均不能只看退出码。

### 1.2 纠正前面几处口径错误

1. 领导要求的是“召回率严格大于 98%”和“精确率保守下界严格大于 30%”，不是“召回率的置信下界大于 98%”。121/123 ≈ 98.374%，已通过召回点估计要求；120/123 ≈ 97.561%，不通过。不要为了过线降低置信度。
2. testset_labels.json 是修复 commit 的引入归因标注，不能等同静态 Risk Point 召回集，也不是那 130 条冻结 YAML。
3. 归因跨仓库可能不可达，不代表同一缺陷不能被静态审查发现。样本是否有效须按任务目标裁决，不能把归因边界直接移植为检测集剔除理由。
4. clone 了仓库不等于深读源码，文章也不天然是浅分析；分析深度必须有读过的文件、符号和验证记录。
5. 模型输出非 JSON、空输出、超时或降级归档，不算评测通过。可靠负结果可算有价值的研究产出，但不能计为优化收益。
6. 仅有文件哈希、禁读提示词或文件访问监视，不等于标签隔离。要限制实际权限，并运行反向读取测试。

## 2. 结构：一个入口，三个相互关联的循环

```text
研究目标与冻结协议
  └─ 外层探索：材料 → 技术点 → 可验证假设 → 候选队列
      └─ 中层实验：基线 → 单机制改动 → 小批对照 → 独立复验 → 扩展 → 终测
          └─ 按需子实验：生产 pattern / few-shot / 规则 / 补证据 / 动态复现
执行统一交给 agent-ops，判定由实验协议约束，结果回写研究账本。
```

不要求每层同时运行，不绑定固定日历周期；按结果或新材料事件推进。静态与动态是领域的验证阶段，不是通用核心固定的两个模型角色。

### 2.1 最少但完整的组织

以下是拟新增结构，不是当前可运行文件清单：

```text
agent-ops/
  scripts/loopctl.py                 # 唯一研究 CLI，薄入口
  scripts/research_loop/
    store.py                        # 事务、事件、状态投影、迁移
    protocol.py                     # 配置、数据版本、冻结、隔离门禁
    experiment.py                   # 候选状态机、对照、晋级、回退
    metrics.py                      # 指标与统计契约
    adapters.py                     # 领域接口、agent-ops 执行桥
    report.py                       # Markdown/HTML/只读状态输出
  templates/tasks/research-*.md      # 提案、实施、独立复核、汇报模板
  tests/test_research_*.py           # 按模块验收，不写成一个万能测试
```

不规定行数。先把职责和接口钉死，出现复杂度再拆模块；不要另建完整调度引擎、安装器或 Web 框架。

SKILL.md 只增加触发入口、边界和最小流程；README 给人类说明与使用例子；ANATOMY 注册模块、数据流和影响矩阵。详细方法以这一份方案及最终实现契约为依据，不在多个文档维护互相矛盾的状态机。

## 3. 通用接入协议：目标、验证与执行分开

一个课题需要一个版本化 project.json，JSON 为默认机读格式，核心尽量用 Python 标准库；确需 YAML 时放到领域适配器并声明依赖。

### 3.1 必填契约

| 组 | 必填内容 | 规则 |
|---|---|---|
| 身份 | schema_version、project_id、objective_version、goal | ID 稳定，目标变更创建新版本 |
| 指标 | metric_id、方向、阈值、比较符、统计口径 | 禁止模糊的“更好”；严格大于与大于等于不能混用 |
| 数据 | manifest、版本、split、关联组、标注等级 | 冻结身份与文件内容，不只冻结数量 |
| 评测 | adapter_id、配置、Judge/规则版本、完整性要求 | Judge 与计分代码不能随候选一起被修改 |
| 候选 | 允许改动路径、候选类型、父版本、回退办法 | 候选改动范围是边界，不允许改评测器制造提升 |
| 探索 | 探索类别、优先级策略、抽样策略、重复与换向规则 | 区分研究类别与具体机制方向 |
| 资源 | 轮数、墙钟时间、模型预算、磁盘、重试、并发 | 外层与子 Loop 共用预算；不各领一份无限预算 |
| 隔离 | 允许输入、禁止来源、身份/沙箱模式、探测方法 | 无隔离能力不能标最终盲测通过 |
| 完成 | 晋级、最终验收、人工复核、停止条件 | 阈值缺失可以调研，不可以自动宣布完成 |

每个指标指定计数单位，例如风险点、告警、commit、查询、运行实例。数据 manifest、评测器与计分规则均计算摘要，记录在每次实验中。

### 3.2 领域适配器接口

同一协议允许 Python 适配器或注册命令适配器；命令用 argv 数组，不用拼接任意 shell 字符串。

- prepare_inputs：按用例导出允许材料，产出输入清单和版本摘要；不得导出答案。
- review：候选方案读取允许材料，产出预测/告警/建议；此进程不能读取 Judge 标签。
- judge：独立身份读取预测与标签，产出逐项裁决；标签原文不回流给留出集的优化者。
- measure：确定性计分、完整性检查、成本统计；返回指标、分子分母、unknown 和证据路径。
- apply/revert：验证候选范围后应用或恢复，仅操作当前实验专属工作区。

不是每个课题都必须有 LLM Judge。单测、基准测试、数值误差和真实运行结果优先；需要模型裁决时固定配置、版本和输出规则，独立上下文，争议进入复核。

执行结果最少字段：schema_version、experiment_id、attempt_id、candidate_digest、dataset_digest、evaluator_digest、started_at、finished_at、execution_status、outputs、evidence、resource_usage。指标结果另包含 metric_id、value、numerator、denominator、unknown_count、coverage、统计方法及参数。

不支持适配器随意运行项目配置中的代码：命令与可写目录须准入。访问商业服务、外部副作用或执行上游工具须按授权边界控制。

## 4. 测试集：可更新，但不能在同一评测中悄悄移动目标

### 4.1 通用 manifest

每条用例：case_id、task_kind、input_ref、label_ref、group_id、split、label_grade、label_status、rubric_ref、provenance、版本摘要。预测输入与标签文件物理分离，不在一个 JSON 中靠删字段“隔离”。

- 精标：人工读逻辑和证据确认；记录审阅者、时间、理由，不把 AI 自评升级成精标。
- 粗标：自动提取或尚待复核的标签，报告单独显示；若计入主指标必须预先规定。
- unknown/disputed：待复核，不自动当负样本，也不临时从分母删除。
- 负样本：定义为冻结 rubric 与范围内经验证无目标风险；“修复过”不保证整个 commit 无其他风险。
- 一份输入可有多个风险点，计分要按风险点去重匹配，而不是看到任一问题就给整条满分。

### 4.2 训练、开发、独立验证、留出、历史回归

- train：允许修改者读取标签并制作 few-shot、通用 pattern。
- dev-discovery：寻找漏因，允许受控反馈；超参和方向选择在这里完成。
- dev-verification：与发现批不重叠，候选与判据锁定后做独立复验。首次验证前不读取其标签；复验结果影响后续选择后，该集已不是永久独立留出集。
- holdout：最终候选冻结后才允许评测身份读标签；预测先封存。结果一旦回流优化，下轮须用新的留出版本。
- regression：保存旧批次，用于交叉回退和防退化；不得再称未见数据。

去重按关联组而非随机行：同一 bug 的引入与修复、孪生提交、backport、相邻版本、相同模板和近似 patch 默认同组。防止一个进训练，另一个进入最终测试。

用户要求的训练正负 8:2、正样本中未召回问题多占比，作为动静结合课题的可配置采样策略，不是所有研究的默认。近五个 tbase 目标版本及其关联修复标签禁止进入训练。

小批开发可以过采样漏报；同时显示各类别效果。不能把过采样批次的总分包装成自然分布总体效果。

### 4.3 更新与坏用例裁决

疑似坏例独立复核，复核材料不含“剔除后涨多少分”。裁决包含可定位证据、任务范围和结论；沿用冻结的替换与剔除规则。

开发集修正形成新版本；对照双方重跑或证明不受影响。最终集按预注册规则处理，规则外的问题列敏感性分析，不能为达到目标修改主分母。

测到 100% 后增补新组，不覆盖旧结果；旧组进入回归，关联组去重后再建新留出。训练与历史经验随版本演进，保留来源和污染检查。

## 5. 指标与统计：能解释“改善在哪里”，不能只给一个分数

### 5.1 缺陷场景的明确口径

- 风险点召回率 R = 唯一命中的有效风险点数 / 冻结范围内有效风险点总数。
- 告警精确率 P = 经裁决正确的唯一告警数 / 纳入计分的唯一告警总数。
- FN = 未命中的目标风险点；FP = 经复核不成立的告警。告警与风险点是不同计数单位，允许一对多匹配时必须冻结规则。
- 重复告警去重，拒绝通过重复输出提高召回分子；额外告警逐项复核，不能丢弃后只算已知标签命中。
- 未审告警显示 pending/unknown，不算 TP。保守口径可将未审告警计入分母且不计入 TP，必须提前锁定。
- 运行失败、截断、缺输入和无法解析是执行/覆盖问题，不是“没有风险”；缺失预测的正风险点按冻结缺失规则计为漏报，同时覆盖门禁失败。
- 超时和重复运行不能只筛成功结果，须报告全部尝试、覆盖率与失败率。

归因准确率、静态风险召回、动态复现成功率、生产拦截率是不同指标，分开建任务与分母，不能直接相互推导。

### 5.2 领导场景的正确映射

固定 130 条 Risk Point YAML 与既定 123 条计分名单；130 和 123 的差异必须有冻结名册及理由，不能猜那 7 条为什么不计分。

终验条件是 R > 0.98 且 precision_lower_bound > 0.30，并且隔离、覆盖和证据门禁均通过。R 是点估计，不能擅改成 recall_lower_bound。

精确率下界的置信度、单侧/双侧和统计单位以既有 Judge/协议为准；未提供时明确标未锁定，禁止终验完成。用于新课题的建议值可为 95% 双侧 Wilson 区间下端，但不能倒推替换既有规则。

Wilson 下端（k 个成功、n 个独立二元观测）：

```text
p = k/n
z = NormalDist().inv_cdf((1 + confidence)/2)    # 双侧区间
lower = (p + z²/(2n) - z*sqrt(p*(1-p)/n + z²/(4n²))) / (1 + z²/n)
```

单侧下界的 z 使用 inv_cdf(confidence)。n=0 返回“不支持估计”，不能当精确率 100%。同 commit 告警往往相关，Wilson 独立假设未必成立；适配器应声明局限，按既有协议或预注册的按 commit 分组 bootstrap 提供补充结果，不在结果出来后挑最有利方法。

### 5.3 通用研究与净收益

通用核心支持计数比例、延迟/吞吐/内存、数值误差、测试通过率、rubric 等。不存在万能分数函数；每个指标由评测适配器计算，原始统计可复算。

净收益先过不可退化门槛，再比较主目标，最后看时间/费用/磁盘。可配置最小收益和非劣容差；不固定 delta<=0 就全面否决。主目标提高但精确率跌穿线、覆盖下降或成本超预算，不能自动采纳。

同批 baseline 与 candidate 使用同输入、Judge、配置和评测环境；随机模型预注册种子或重复次数。必要时交错运行对照，记录波动，不以一次好运判定机制成立。

## 6. 探索空间、策略与提效：AI 提方向，实验决定去留

### 6.1 技术点台账

每个 idea_id 记录：来源及版本、类别、适用前提、机制假设、目标漏因、计划改动、反证办法、成本预估、已有尝试、状态和关联实验。

三类探索轴：知识上下文、提示词工程、用例正确性。工具接入可以是知识/方法中的一个机制；数据修正必须进入独立的数据质量流程，不能悄悄与算法候选混跑。

例如：祖先历史补证、Joern 数据流查询、Semgrep 局部规则、TLA+ 规约验证、同语言历史 pattern、few-shot 选择、日志预测核对。工具不是默认必用：依据证据缺口决定，不为堆工具或报告而调用。

输入既可来自现有 radar 台账，也可来自文章、用户建议、开源/商业工具。tech-radar 专项当前不被 agent-ops 自动消费；接入必须增加显式 opt-in 适配器，不扩大原 check-new 的 briefs 扫描边界。

对来源进行指纹去重和版本记录。AI 不能只因文章自称有效就采纳；调研结论分“材料声称、源码可证、本地可复现、领域适用未验证”。

### 6.2 每轮纪律

1. 选一类值得解决的漏因，提出一个机制假设，不一把梭改 prompt、工具、标签和评分。
2. 记录当前 incumbent、候选 diff、机制 ID、对照批次、验收条件和反证方案。
3. 本批 10 条开发用例上 baseline/candidate 对照，记录 TP、FP、FN、unknown、耗时与成本。
4. 连续两轮有效实验无净收益，换 mechanism/direction，保留负结果。不要只改 kind 名字规避换向。
5. 同一候选内容摘要在两批互不重叠开发用例通过，第二批独立复验，才允许扩展。改了候选摘要，重新验证。
6. 扩展批检查历史回归和成本，候选/Judge/分母/剔除规则锁定后才终测；130 条只在最终阶段运行。
7. 通过才采纳；未通过可回退、换向或阻塞，不能把归档标成成功。

10 条是此场景的开发批大小，可配，不等于 10 个风险点。小批达到目标不证明总体达标；最终结论仍来自冻结正式集。

### 6.3 进化式探索但不盲重试

成功方向先独立复验，再扩大；失败方向按原因决定是否重试：证据不足补材料、执行失败修环境、真实无收益保留一次预算内反证/复验机会。已证明不成立的前提不无限重试。

优先级可由预期收益、验证成本、不确定性和未覆盖漏因组成，所有排序参数版本化。保留少量探索预算给新方向，避免只追高分旧路线。

先单机制，再验证组合；组合必须指向已验证父候选并做消融，记录父候选、相互作用和回归。不是全空间排列组合暴力枚举。

策略本身的优化以“单位真实实验成本带来的有效收益、无效尝试率、覆盖新机制数、等待与复用时间”评估；生成更多想法不算效果。

### 6.4 pattern 子 Loop

从训练侧历史缺陷抽象 pattern → 正负例与适用边界 → 独立开发验证 → 稳定的规则/知识卡。

子 Loop 与外层共享预算；有 parent_experiment_id、输入摘要、产物版本、失败原因。限制递归深度与并发，禁止循环依赖。子 Loop 通过不能替代外层领域评测；只有外层也通过才影响生产候选。

## 7. 提示词与代码理解验证

使用任务模板生成具体 prompt，不要求用户自己写几十条纪律。便宜模型也必须拿到目标、当前候选、允许输入、最小复现办法、输出 schema 和停止条件。

few-shot 必须有：来自允许的训练集，至少覆盖正确发现、反证无风险、边界不确定；例子附证据与裁决理由。禁止从正式留出标签提炼示例，也禁止把项目 SHA/修复答案硬编码进通用规则。

要求模型输出可审计的结论依据：前提、相关符号/分支、证据坐标、反例、验证脚本和未验证点；不依赖隐藏思维过程或长篇 CoT 作为正确性证明。

主输入以 diff 为入口，缺上下文再经允许接口获取目标版本函数、变量、调用链与历史，不机械截断，也不把整个仓库无差别塞给模型。

动态验证可先预测日志、状态变化和失败条件，将预测封存后再运行真实单测/复现。对比真实日志时区分环境差异、触发条件和语义错误；预测与日志一致仅证明该测试路径，不证明完整代码理解正确。业务知识与日志作辅助，不把未来修复信息作预测依据。

深度状态不用“仓库=深，文章=浅”的猜测，记录：材料摘要、源码证据、局部验证、动态复现、独立复验。每阶段均列已完成、进行中、失败、未验证；阶段内容保留真实文件/符号坐标。

## 8. 隔离、Git 快照与动态效率

### 8.1 防泄漏的实际边界

修改者可以看训练和已开放开发反馈，最终 reviewer 不能看标签、历史评测、后继修复、其他 agent 会话或评测结果。

父控制器准备输入，reviewer 在受限身份或已验证沙箱中运行；标签由 evaluator 单独读取。禁止源不能与允许源码一起挂载，也不能把全权限 CLI 的“只读这些”当安全隔离。

开跑前验证：直接文件读取、相对路径穿越、符号链接、git log/show 后继提交、原仓库 .git、网络获取修复、共享目录/进程环境等通道。默认 reviewer 禁网，确需工具或来源先由父侧审查并缓存；禁止 token、标签路径进入 prompt/日志。

文件监视和哈希是审计补充，不是权限控制。没有能阻断禁止来源的执行环境，开发实验可以标 limited_isolation，正式终验必须 blocked。

候选、Judge、计分名单先冻结，随后运行预测、封存摘要和时间，再允许 evaluator 开标签。开封事件只追加。最终失败不得原地针对标签调优并重测同一留出集当“新盲测”。

### 8.2 Git 与磁盘

父侧复用一个只读对象库；按 repo、commit、文件、工具版本缓存上下文。能用 git show/log/blame 的不创建全量快照。

对 reviewer 导出目标提交的允许文件和 diff，历史只能经父侧的祖先可达查询接口提供。完整 git 仓库里有后继修复，即便 checkout 在旧 SHA 仍可泄题；worktree 也共享对象库，不能单凭 checkout 证明隔离。

函数链/变量索引可复用，但必须与目标 tree 和索引器版本绑定；最小上下文不足时继续补，不承诺离开快照永远足够。

确需编译的实验使用独立构建区，避免改用户当前分支。Git worktree 仅用于非盲阶段或可信父侧构建；使用它不自动获得标签隔离。

### 8.3 动态验证与缓存

先最小单测/局部复现，验证有效后再端到端；锁管理、并发等问题要记录调度条件和重复次数。模型检查反例不自动等同真实程序 bug，须验证规约与代码对应关系。

缓存键包含源码树、patch、编译器/依赖、配置、测试命令、运行环境和适用输入。只改研究 prompt 且构建输入不变时可复用编译；影响编译的变更必须失效。测试结果不能因为复用构建而复用。

报告 cold_build、cache_hit、review、judge、run、queue_wait、recovery 的耗时，给出总墙钟和各阶段成本，不把缓存收益算作检测质量收益。

缓存 TTL/容量、活动租约和路径归属都要检查；只清实验缓存，不清证据、台账或用户仓库，不做 broad rmtree，不绕过环境安全确认。

现有雷达规范禁止运行上游代码。需要真实验证 Joern/Semgrep 等，应进入另外的准入实验环境：可信版本、依赖锁定、隔离工作区、授权与限资源；不能修改规范后让所有 radar clone 自动执行。

## 9. 持续运行与落盘：同一实验只有一条可信事实链

### 9.1 状态分离

分别记录：

- 执行：queued / running / retry_wait / succeeded / failed / blocked / canceled。
- 证据：pending / valid / invalid / incomplete。
- 实验：untested / beneficial / no_gain / regression / inconclusive。
- 候选：proposed / approved / applied_in_trial / screening / verification / expanded / final_locked / accepted / rejected / rolled_back。

taskctl done 只映射执行结束；result.json 完整、证据有效、计分通过后才进入实验结果。阶段晋级靠机器门禁，模型不能直接改 accepted。

可靠失败实验是已完成研究，不是完成优化；未获真实验证的候选必须明确标未验证。

### 9.2 运行目录与职责

配置和人工可维护规则放项目仓库；运行数据默认放用户数据目录，支持 RESEARCH_LOOP_HOME 覆盖。不把大量运行文件散落在 agent-ops 根目录。

```text
<运行根>/<project_id>/
  state/research.db                  # 唯一研究状态/事件权威源，SQLite
  protocols/<version>/              # 冻结配置与数据/Judge摘要
  ideas/<idea_id>/                   # 来源、假设、前提、验证方案
  experiments/<experiment_id>/
    plan.json                       # 本轮预注册、候选及输入摘要
    attempts/<attempt_id>/
      inputs/                       # 允许输入，不含标签
      outputs/                      # 原始预测和产物
      evidence/                     # 运行回执、日志、工具输出、裁决
      progress.md                   # 子 agent 当前步骤与阻塞
      result.json                   # 执行契约，不是最终指标账本
    candidate/                      # patch、配置、知识卡版本
  reports/                          # 自动生成 STATUS/CHANGELOG/REPORT/HTML
  cache/                            # 可回收；不能与永久证据混放
```

标签 vault 独立于 reviewer 可见运行目录。manifest 中的标签引用只对 evaluator 解析。实验名用稳定 ID，不以日期为唯一索引；时间是属性。

### 9.3 原子性、幂等和恢复

研究 SQLite 保存 experiment、attempt、metric、artifact、decision、event 的关联。状态与事件同事务；大文件先临时写入、校验后原子替换，再登记路径和摘要。

派单用 experiment_id+stage+attempt 的幂等键，登记 outbox 再调用 taskctl，保存真实 task_id。桥接端按任务关联查询并对账，处理“任务已创建、回执未保存”的崩溃窗口，不能盲重派。

证据文件不覆盖，重试新建 attempt。宕机后重新核对租约、实际任务与产物，继续未完成阶段。SQLite 崩溃恢复、事件与文件缺口均须故障注入测试。

运行日志增长不作为唯一判活，沿用实际会话与 progress；supervisor 决定续接/诊断/交人，执行封装做精确进程归属检查。限流按现有通道逻辑恢复，不新增无限快速循环。

重试预算按课题和子任务累计，达到上限进入 blocked/inconclusive。预算包括所有失败和重试；无法取得实际 token/费用时标 unknown，不能报 0 费用。

### 9.4 三份 changelog 不混用

- agent-ops/CHANGELOG.md：技能本身的代码与契约变更。
- radar/LEDGER.md：来源调研、借鉴及处理记录。
- 项目 reports/CHANGELOG.md：逐轮实验，自动从 research.db 生成，不能手改制造结果。

每轮记录：探索目标、来源技术点、假设、优化原因、机制、候选摘要、父版本、数据/Judge版本、对照批、TP/FP/FN/unknown、指标与下界、阶段耗时、费用、判定、反证、回退、未验证点和证据链接。

修正错误追加 correction 事件及理由，保留旧值。不删失败史；渲染最新视图时显示已更正。运行日志按字节轮转，证据按保留政策归档；备份/恢复不能只备 reports 而漏数据库和原始裁决。

## 10. 可视化与汇报：先看研究，不先看杂乱日期

先生成自包含只读 HTML，无前端依赖。若需要自动刷新，再提供最小只读服务/API；从同一账本读取，不能另建前端状态数据库或凭浏览器请求推进任务。

页面结构：

1. 目标区：指标、阈值、数据/Judge版本、基线、当前最佳、最终验收状态。
2. 探索区：知识/提示词/用例质量分类，具体机制、前提、尝试数、收益、成本、为何换向。
3. 轮次区：基线→对照→复验→扩展→终测，每轮的净收益和耗时；点开直接查看证据。
4. 数据质量区：精标/粗标/争议、split、泄漏检查、覆盖率、FN/FP 类别。
5. 运行区：进行中任务、限流、阻塞、重试与恢复；不把 queued 显示成“已分析”。

报告统一三段：整体规划与进展；问题波折与解决证据；后续目标、待验证假设与资源计划。附可复算指标表，不报模型主观评级代替效果。

导航可收起、内容宽度适配、表格滚动、浅深色对比度、键盘操作；全部材料统一一个课题入口，内部链接跳具体实验，不把日期当主目录。

只读页面动态状态取真实事件时间，不能用每次请求的当前时间冒充最近进展。验证时真正打开浏览器截图、点击目录、证据和状态刷新，不能仅 grep HTML 关键字后宣称界面可用。

## 12. 交给实现模型的顺序：每步可停、可验收、可恢复

下列 loopctl 子命令是拟实现接口；当前不存在，不要在实现之前执行或写进 README 当已交付。

### 阶段 A：契约与干净组织

读当前 SKILL/README/ANATOMY/GOVERNANCE 与代码，记录 git status，保留其他会话改动。建立最小协议、状态分离、运行目录、JSON schema 校验及测试，不先改原任务调度语义。

拟命令：loopctl init / doctor / status。doctor 默认只读；安装明确 fix 模式，下载来源经审核、参数不经 shell 拼 token、验证返回码和版本、安装后重新探测。Node 要解析真实主版本>=18，不用 v1/v2 前缀猜。真实模型 smoke 独立且限成本，失败绝不因路径存在被提升为 ok。

验收：非法协议拒绝、版本明确、目录不污染根目录、现有命令兼容。先不自动安装/升级用户已可用 CLI。

### 阶段 B：账本、指标、报告

实现 schema 迁移、事务事件、artifact摘要、逐项指标、实验结果导入、报告生成。

拟命令：loopctl record / metrics / report。先用夹具验证工程逻辑；这些是工程测试，不是领域性能证据。

验收：所有图表和 Markdown 数值可由同一原始裁决重算；未验证、失败、unknown 清晰区分。

### 阶段 C：执行桥与一轮真实对照

通过 taskctl 派任务，不再自己实现后台进程池；实现 attempt 幂等、outbox 对账、严格结果验收和独立 Judge。

拟命令：loopctl baseline / propose / trial / tick / resume / pause。

先跑一个真实、低成本、公开答案与预测进程隔离的最小工程课题，再接用户领域。记录真实 CLI、脚本、任务回执和成本；不靠伪造 JSON 演示自主优化成功。

验收：baseline 与 trial 同批对照、只改允许机制、空输出/error JSON/超时/非 JSON 不计成功；恢复后不重复应用候选。

### 阶段 D：冻结、隔离、晋级与回退

实现数据分组切分、独立复验、隔离探测、候选冻结、预测封存、最终集开封、采纳与回退。

拟命令：loopctl verify / expand / lock-final / final / adopt / rollback。

验收：未双批通过不能终测；候选/Judge/标签版本变了不能继承验证；盲测失败后同留出不能再伪装未见集。隔离不支持则明确 blocked，不退化为提示词禁读。

### 阶段 E：持续探索、子 Loop 与动态提效

实现来源显式接入、技术点台账、方向优先级、连续无收益换向、有限复验、子 Loop 预算继承和缓存键。

拟命令：loopctl idea / explore / child / budget。具体选方向由 AI 提案，机器校验范围与预算。默认关闭自动外部通知。

验收：一次真实失败→诊断→重试/换向→结果；一次 pattern 子 Loop→外层验证；一次构建复用/失效对照。没有商业授权的工具不阻塞其他可验证方向。

### 阶段 F：界面、交接与领域终验

实现第 10 节的单入口页面，真实截图与点击验收。补齐 SKILL/README/ANATOMY/CHANGELOG，安装副本按用户范围同步；本次内网交付不擅自发布公开版。

接动静结合适配，核对真实集与计分规则后做领域实验。系统工程验收与领域达到阈值分别报告；未拿到最终输入时可以完成平台实现，不能宣布领域指标已过线。

完成交接列：修改文件、可运行入口、测试证据、真实实验、当前最佳、无收益方向、未完成输入、运行状态、恢复办法、报告入口。

## 13. 必测清单与总完成条件

### 13.1 工程回归必测

- 指标：121/123 的召回严格通过 98%，120/123 不通过；30% 等于阈值不通过；空分母不通过；重复风险点/告警不重计；缺失预测/未审告警按协议处理。
- 统计：95% 双侧 Wilson 40/100 下端约 0.3094，30/100 约 0.2189；单侧/双侧区分；相关样本声明与分组方法不能后选。
- 数据：关联组不跨 split、精粗标分报、坏例裁决可追溯、数据变更失效旧验证、旧组回归保留。
- 状态：done 无 result 不晋级；降级文本不当成功；同候选双批才扩大；连续两次有效无收益换机制；执行失败不冒充无收益。
- 隔离：禁止文件、符号链接、未来 git 对象、共享会话和网络来源读取失败；标签只被 Judge 读取；先封存后开封有证据。
- 恢复：派单前后、文件写入前后、计分入账前后分别注入崩溃；恢复无重派/重复应用；事件与投影一致；数据库忙与损坏有明确信息。
- 资源：子 Loop 不逃逸预算、限流/超时有上限、active 缓存不被删、构建键改变失效、费用未知不报零。
- 安全：路径约束、argv 参数化、密钥不入库、不杀其他任务、不删除用户工作区、不执行未准入上游脚本。
- 前端：宽屏和窄屏截图；导航可收起；状态真实更新；空数据/错误有反馈；表格/链接可操作。
- 文档：拟接口已实现才列能力；代码、CLI、README 和状态名一致；没有无效占位符与历史旧计分口径。

### 13.2 开发门禁

实施时按 GOVERNANCE 运行现有 pytest、doccheck、anatomy_check、agentctl status 及其 JSON 路径、pyflakes。新增机制必须有新增测试，不把现有测试绿灯当新 Loop 已测证明。

新增 CLI 必须跑实际 init/baseline/trial/resume/report 业务路径；--help 与模拟导入不能替代真实运行。测试工具故障与领域指标失败分别留痕。

### 13.3 最终“做好了”的定义

只有以下均成立才叫通用 Loop 工程交付完成：

1. 用户可给一个目标与适配器启动课题，核心不依赖特定仓库或领域名。
2. 能完成真实基线、单机制候选、同批对照、独立复验、扩展/终测门禁与采纳/回退。
3. 有实际权限隔离和反向探测；缺能力明确阻塞，不虚报盲测。
4. 宕机后接续可信，方向无收益会换向，预算耗尽会停止，不靠人不停贴“继续”。
5. 每轮原因、技术点、效果、假阴假阳、时间、费用、证据清晰落盘，同一入口能复盘和汇报。
6. 规则/pattern 子 Loop 有独立证据且接受外层验证，策略与缓存收益可量化。
7. 旧 agent-ops 编排、监督、雷达及其他运行任务不被破坏；安装探测不误报成功。
8. 报告清楚区分“工程完成”“研究负结果”“目标未达标”“最终验证通过”。

本方案不承诺无限运行、不承诺所有工具适用、不承诺通过指定指标。承诺的是：有边界的自动探索、真实可复算的效果、可靠恢复、负结果和失败不被抹去，以及下一步有证据地推进。
