# 多通道模型选型：发现、白名单、成本闸门

> 本文给方法，不给任何平台的模型清单与价格。模型清单会过期，价格会调整——**以你所用平台的面板和计费说明为准**。

## 一、发现：哪些模型真的能用

1. **列候选**：用 `--help` 或平台面板列出全部模型。注意 `--help` 往往把付费档一起列出，不要据此判断免费与否。
2. **实测调通**：一个模型「存在于列表」不等于「你的凭证池允许它」。逐个发一条最小请求，记录成功 / 失败与错误文案。
3. **记错误类型**：`未被可用凭证池允许` / `不支持该模型` / `模型不存在` 是配置问题，不是限流；和 429 分开归类。

产出：一张「实测可用」清单，附每个模型的上下文长度、是否支持思考档位、是否支持识图。

## 二、白名单：把选择收窄到可维护

维护一个项目级白名单，而不是让调用方随便传模型名：

- **凭证池配置**里写 `allowed_models`（按通道分），只放实测可用且成本可接受的模型。
- **代码层**在发请求前用 `assert_model_allowed()` 校验，命中白名单外直接拒绝。
- **不要依赖 429 自动回落**选出模型——回落可能落到更贵的模型，成本不可控。

## 三、成本闸门：先定口径再定阈值

计费方式有三种，处理方式不同：

| 计费方式 | 怎么读 | 怎么控 |
|---|---|---|
| 绝对价格（元 / 千 token） | 直接看出来 | 按预算设单任务上限 |
| 相对倍率（credits，x 倍） | 倍率不是价格，x0.00 通常是不扣费 | 设一个倍率阈值，超过即拒 |
| 额度制（次 / 天） | 有明确配额 | 用速率预算 + 天级闸门 |

**实现要点**：阈值写成常量 + 环境变量可覆盖；校验在请求前，不在响应后。把「免费档」和「便宜档」分开配置，默认只用免费档，需要提速时显式开便宜档。

## 四、跨通道命名对应

同一个模型在不同 CLI 通道里 ID 可能不同（大小写、后缀、别名）。做法：

- 建一张 `{"通道A名": "通道B名"}` 的别名映射，调用方写哪个都能路由到正确模型。
- 记忆口诀：带某后缀的名字通常只属于某个通道，喂给另一个通道会报「不支持该模型」。
- 出现「解析失败：不支持该模型」先查命名，而不是查签名或参数。

## 五、选型决策

| 场景 | 选择 |
|---|---|
| 默认干活 | 免费档里上下文最够用、支持思考的旗舰模型 |
| 批量短任务 | 免费档里的快速模型，超时设短（如 25s），失败不重试留待下轮 |
| 识图 / 多模态 | 单独一档支持视觉的模型（旗舰文本模型可能不支持识图） |
| 长上下文 | 选 1M 级上下文的模型，但注意单价可能更高 |
| 监督 / 裁判 | 与被测模型**不同的另一个模型**，避免自己判自己 |

## 六、双模型交叉验证

多模型场景的一个实用模式：**被测模型与裁判模型必须是两个不同模型**。同一模型自己判自己测不出偏袒；交叉验证能暴露单模型的结构性盲区。

实现：`MODELS` 池里至少两个模型，按条轮转，裁判固定用池内另一个模型。

## 七、慢模型与快模型分开设超时

同长度 prompt 下不同模型耗时差异可达数倍。统一超时会误杀慢模型：按模型设不同超时（快模型 90s、慢模型 150s 之类），并在日志里记录每个模型的耗时分布，据此调整。
