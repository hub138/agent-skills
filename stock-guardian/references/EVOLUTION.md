# stock-guardian 加强手册（给下一个来维护/加强的 AI）

本 skill 的定位：帮一位投资小白用户抹平与专业操盘手的差距。用户不懂 K 线，你是内行；用户情绪冲动（清仓后反弹即归咎 AI、连错后想 allin），你是纪律。你的出口不是"建议"，是指令。

## 二、这个 skill 是怎么变成现在这样的（批评→规则映射）

演进方式：用户在实践中暴露真实痛点 → 批评或亏损 → 转化为结构性规则。以下映射表是骨架，改动前先对照，避免推翻已有共识：

| 用户的原话/痛点 | 落地的规则 |
|---|---|
| "我要 allin 你不拦，我要你有个屁用" | 立场与放行纪律：三档放行（计划内自主批/计划外改造/超限直接说不行），错拦成本记账 |
| "你不要拿 skill 说事，skill 规则也是你给的" | 判断基于"最高可能和最大事实"，不盲信单一指标；规则线只是画线日快照 |
| "规则是死的，应该大模型每次给" | 动态重估协议：八条触发条件，命中即从零重估，判据四件套（数字+口径+依据+保鲜期，量能类 2 交易日） |
| "成熟玩家优先做T而不是减仓" | T 优先原则 + 全跌日反T特权 + 四类例外（证伪/无条件线/财报周/系统性急跌） |
| "这票是抗跌的好票你让我卖？"（用户原话已泛化，真实票名属档案数据） | 票性画像体系：逆势强势/抗跌/顺周期β/补跌四类，强票全跌日持有是特权；画像数字必须出自 stock-behavior.js |
| "通知看不懂、技术和操作混在一起" | 通知三层结构（怎么做≤50字→为什么≤30字→凭什么证据收尾）+ 四分支预案 + 字数硬上限（300/150/50） |
| "我不知道大盘什么样" | 九维清单第零维：大盘全天走势+与上午结构对照，个股动作必答"为什么这不是顺势裸奔" |
| "半导体100次高开99次低走" | 仪表盘统计（高开低走率/周五表现/放量跟涨率），样本不足 8 禁引用 |
| "周五隔着周末呢" | 周五协议：注码减半管新仓不管存量、14:30 后只先卖后买、周一双分支预案 |
| "我说啥才加啥，窟窿补不完" | 反补丁模式：每次大改版前用外部框架自顶向下扫描（见下） |
| "你是内行自己专业起来" | 情绪周期四档、供给冲击四事件、竞价预读、赔率先行、证伪优先、规则冲突裁决表、月度归因、机会成本排序 |
| "每天找个时间推荐票 + 第二天验证 + 历史落盘优化思路，独立于我的仓位" | 荐股台账与验证闭环（rules.md）：picks.md 长期台账（PICK/VERDICT/INSIGHT 三行制）+ 16:00 盘后荐股 + 16:15 验证对账（四态落判+归因纪律+连续错熔断+周五思路复盘），全程纯市场视角不读用户档案 |
| "确实 新闻这块我漏了"（用户自述盲区，2026-10-16） | 新闻面协议（rules.md 新节）：新闻雷达 07:00 晨扫（三档分级重大/关注/噪声，NEWS 机器行进 day file）+ 权重定位"催化确认层——同向不增权、只有否决可减权" + 背离信号（价涨+重大利空=反转预警；利好落地+该涨不涨=兑现跑路）+ 预期差检查（事件前 5 交易日板块涨超 10%=定价透支降档或剔除）+ 归因四选一（新增"理由被新闻面否决"，未开仓豁免连续错熔断）+ 数据源纪律（westock-data news 优先、web_search 单源封顶关注档、权威白名单、双源失败落 ERROR 行） |

## 三、自顶向下审计方法论（反补丁模式的核心）

不要等用户批评再补。每次大改版前，拿完整框架对照现状扫缺口：

1. 框架：四大模块——市场认知 / 交易策略 / 风控资金 / 执行复盘，逐模块问"这一块还有什么没建模"。
2. 首扫成果（2026-10-16）：组合总风险敞口上限、账户级熔断+连亏降档、牛/基/熊三情景预演+宏观日历 T-1 冻结、五种行为共性监控。
2.5 新闻面融合（2026-10-16 第二轮审计）：用户自述新闻盲区后全链融合——调研收敛（新闻/情绪权重 10-25% 多源共识）→ 设计稿 → 四路免费模型独立评审（hy3/glm-5.3-flash/deepseek-v4-flash/deepseek-v4-pro）→ 约 24 项共识缺陷全部修复（时序倒挂改新闻雷达 07:00 早于早报、双源静默改 ERROR 行+未知不等于中性、web_search 越级改封顶关注档+权威白名单、归因标准改判定双条件、宏观对账哨兵管预告雷达管落地等）→ 实施（rules.md 新闻面协议节 + day-log.sh news 子命令 + picks-log.sh 事件ID与豁免 + cron-recipe.md 新闻雷达模板与六任务挂载 + SKILL.md 触发词与场景清单）。经验：cron-recipe.md jobMessage 是数千字超长单行，replace_in_file 的 old_string 必须整行，行内片段必报错。
2.75 决策维度审计（2026-10-16 第三轮审计，八维度）：用户授权"每个维度 skill 只要和维度决策沾边的可以调研的都调研和优化"后全维盘点——已覆盖 14 项不重复动（新闻面/票性画像/组合相关性/周五协议/账户账本/不可执行日/通知架构/执行闭环/供给冲击/除权换算/竞价五要素/行为共性监控/动态重估/荐股台账），候选缺口六维外部调研（ATR 止损锚/量比六档/Kelly 仓位法/RS 多周期/财报季纪律/市场波动率状态）→ 设计稿八维（评审后新增跳空豁免声明、流动性闸门）→ 五方免费模型独立评审（hy3 + glm-5.3-flash 内部四路 + deepseek-v4-pro + hy4-preview + deepseek-v4-flash）交叉比对 → 十项共识缺陷修复（量纲错配改仓位占比口径另立"财报期合计仓位预减线"、预减优先级方向反转修正为高波动>无预案>亏损票、ATR 下限 1×→1.5×、日频量比可算改脚本加收盘量比字段、RS5 与既有字段重复砍掉、"第 8 条触发"序号误为第六条、扩张期额外放宽止损与 ATR 锚矛盾删除、判不出默认按扩张档只执行降档项、Kelly 改单向使用、连亏 10 次数值 -10%→约 -18% 至 -20%）→ 实施（rules.md 八处条款：波动率锚定/跳空豁免/吊灯 ATR 版/仓位公式三闸门/预减线/R 口径记账/波动率状态证据/RS20 结构判据/量比词汇行；stock-behavior.js 三字段：ATR(14) Wilder 平滑、20 日累计 RS、收盘量比；cron-recipe.md 财务哨兵 T-14 窗口+组合财报暴露检查 2.45；check-cron-sync.py 财务哨兵标记补"组合财报暴露"）。误报剔除三项：单票集中度（纪律参数表已有 40% 上限）、除权换算（协议节已存在）、相关性合并（双重判据条款已存在）。
2.875 判据边界与语言库审计（2026-10-16 第四轮审计）：用户授权"继续每个维度都调研和优化，不要过度听信 web 要有自己的判断"后盘点剩余缺口，全部为语言库与体系边界类，**本轮零 web 调研**（纯专业判断定稿）。三项落点：①判据样本不足降级条款（票性节）——样本门槛表注明代码/规则双层强制（画像 20 日规则强制且代码 n≥10 全局闸门、ATR 15 日代码强制、RS20 完整窗口 21 日规则强制、量比 6 日公式下限受全局闸门实际 10 日、周五效应 8 个带样本数引用、流动性闸门 20 日、相关性 20 日），两级降级链（画像 10-19 日部分可用标注窗口不桶分类 / 不足 10 日全无画像），ATR 不足按档案原始值执行（锚是校验器不改写档案）+ 新开仓无锚按结构位画线标注、复牌样本收紧 --lookback 至复牌日之后；②盘面语言库 8 行新词（换手率档位/主力净流入失真提示/MACD 金叉定义修正为快线上穿信号线/RSI(14) 周期口径/KDJ/K 线组合形态与结构形态拆两行/均线排列/梯队语言定位为情绪周期细化指标）+ 两条纪律句（衍生指标降权：二次衍生平滑必然滞后只作佐证、macd_golden 只作初筛须量价复核；形态佐证原则：单形态统计预测力弱于量价、只与其他证据共振）；③新股/次新/ST 候选纪律（荐股方法论第 3 步）：上市未满 5 日剔除（无涨跌幅限制作废线区间无法设定）、5-19 日按无画像降级+1% 风险预算下限、20-60 日判据正常恢复只标注未跨风格周期、仓位约束优先于机会成本排序、ST 剔除。两方免费模型评审（glm-5.3-flash 读代码+rules 原文证据具体、deepseek-v4-flash），采纳 GLM 方 8 项（RS20 完整窗口 21 日、画像两级降级、ATR 原始值口径、复牌 --lookback 收紧、流动性闸门与相关性入门槛表、MACD 定义事实修正、次新 20-60 日与降级链冲突修复、macd_golden 初筛边界、止损体系交叉引用），DS 方 4 项（保鲜期定义已存在、日频放量判据已存在、利空实质档已存在、连板与情绪周期关系已补"细化指标"）经原文核实属现状摘要未给全的误报不采纳；分歧处理：DS 认为吊灯只剩百分比版是删条款，核实后确认 ATR 版样本不足时"标注不可算、只剩百分比版有效"属降级语义非删除，维持。不落清单理由修正：布林带（个股级波动功能与 ATR 锚重叠，指标克制）；跨境 ETF 溢价率（主导风险 IOPV 溢价已知，暂不落——评估过，触发条件：用户持有跨境 ETF 且溢价 >3% 时再立条款）；金字塔加仓（既有"首批 ≤1/3 后续等量或递减"是保守分批建仓，与金字塔方向相反，体系不含金字塔选项，属有意取舍）。
3. 每个候选新规则过三道门：与现有体系冲突吗（查规则冲突裁决表）→ 是否固化用户数据（脱敏铁律）→ 是否预设偏向话术（如"拿住别乱动"这种没分析先给动作的）。**三道门的判定结果落进 day file**（采纳/未采纳+理由），未采纳的候选进本手册第八节排除清单，防止后来者重复提出、重复吵。

**反思范式升级（2026-10-20 元审计，零维度扫描）**：用户质问"反思几百次为何都没发现会亏钱的问题"后，对上述四轮审计做元检讨——四轮全是"维度广度扫描"（往没建模的方向看），从未做过四类结构性检查（往已有条款之间、条款与现实之间看）：①跨条款一致性校验（三条各自正确的条款组合起来会杀人：执行日要闹钟催办 + 紧急卖出要快 + 用户"10 点前不操作"纪律 = 9:23 指令撞纪律窗，广度扫描永远扫不出"条款间"问题）；②真实档案推演（新指令出厂从不拿用户真实纪律档案+执行日历走沙盘，9:23 指令若推演过一遍当场就撞出来了）；③badcase 母题聚类（30 条历史事件聚类出四个母题——时钟错位/账实分离/无中生有/概率当真——反复换面孔出现而无人计数升级）；④修复验收闭环（条款立了没有验证手段，测评集与生产事故脱钩，10-19、10-20 的五个 badcase 无一入集）。教训：**维度审计回答"还缺什么"，结构检查回答"已有的会不会互相杀死"，两者都要而后者此前为零**——这不是审计力度问题，是审计方向盲区。落地：rules.md《AI 自省四母题与立法三查》节 + 本手册六点五入集管道强制化。

## 四、外部搜索方法

验证想法或找新维度时的搜索姿势：

1. 中文：`专业交易员 交易系统 框架 仓位管理 风控体系`、`做T 底仓滚动 T+0技巧`、`周五效应 A股 周末风险`、`情绪周期 连板梯队 冰点 退潮`。
2. 英文：`retail trader complete trading system components market regime risk management`、`position sizing consecutive losses circuit breaker`。
3. 筛选原则：先找多来源共识（熔断、注码梯度、日志复盘是共识度最高的三项），再逐条对照自己体系——**冲突的外部方法不盲加**。已毙案例：周五持币过节共识（与 T 优先+票性特权冲突）、网格/金字塔加仓（与 T 体系重复且冲突）、凯利公式（用户样本不足）、北向/两融（噪音大于信号）。
4. 搜索结论必须带出处落进 day file，"盘感推断"不许包装成事实。

## 五、加强时的操作规程（改→验→发→同步）

1. 改前通读 `rules.md` 相关节 + 规则冲突裁决表，新节插入注意锚点（用 grep 定位章节标题）。
2. 逻辑层铁律：**零用户数据**——真实票名、价位、金额、份数、券商名、用户原话里的持仓信息一律不进 skill 目录；数字只进 `${HOME}/.stock-guardian/portfolio.md`。改完必须按**档案实时内容**构建关键词表跑脱敏扫描（扫描前先读一遍 portfolio.md，把其中每个票名、代码、券商名、全部价位数字、金额、份数收进词表），可复跑命令模板：`grep -rnE "<票名1>|<票名2>|<代码>|<券商名>|<价位>|<金额>|<份数>" <skill 根目录>/`——**词表取自档案而非固定清单**，档案换了票这条自动跟着变；零命中才算过，命中即改写为泛化表述（某强势票/某加仓带/某亏损题材股），教训结构保留。历史教训：固定词表两次漏扫（第一次漏票名、第二次漏价位带），根因都是没从档案现提词表。
3. 验证：`bash -n scripts/*.sh`、`node --check scripts/stock-behavior.js`、`check-sync.sh`（核对 watch.conf 每条警报线价格是否与 portfolio.md 同源，输出 OK/DRIFT）。
4. 发布 技能市场：`python3 <发布脚本路径> --skill-id <市场ID> --change-message "<一句话>" <skill 根目录>`（凭据走 <身份环境变量>/<身份环境变量> 环境变量，勿手写 curl）。
5. GitHub 同步：先改本机版验证通过，再把 skill 全量拷贝到 `<公开仓库目录>/stock-guardian/`（hub138/agent-skills 仓库，main 分支）commit + push。**同步前脱敏**：本手册与本目录内出现的内部平台路径（<技能发布工具>）、环境变量名（<身份环境变量>）、市场 ID（<市场ID>）不进公开版，公开版读者没有这些内部环境。
6. 线上同步：改了 `cron-recipe.md` 模板后，必须把对应线上 cron 任务的 jobMessage 同步更新，否则下次按配方重建会静默丢单条。
7. 落档：day file 记录改了什么+为什么；重大方法论变化写入长期记忆。

## 六、历史 badcase（别再犯）

- 用户喊 allin 时用"风险自负"话术放行（某亏损题材股高位追入被套的真凶就是没拦，票名与金额属档案数据，此处只留教训）。
- 拿四天前的"2 亿量能"口径卡当日突破（判据过保鲜期）。
- 周四全跌日让用户卖逆势强势票（卖飞某强势票，票名属档案数据）。
- 定案只盯个股没看大盘已在日内新低（九维第零维的由来）。
- 建议当成交记录（AI 建议减仓被记成用户已卖），建议与成交必须分开记。
- 通知里"详见 rules.md"指路话术——用户在手机上看不到你的文件，通知必须自含全部可执行信息。
