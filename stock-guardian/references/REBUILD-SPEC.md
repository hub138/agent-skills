# stock-guardian 收敛式重构规格 v1

## 1. 唯一目标

在约 5 万元、A 股 T+1、人工下单、偏好持有 5—10 个交易日的约束下，提高**扣除全部成本后的账户净收益**并控制最大回撤。通知数量、脚本数量、模型输出长度都不是目标。

系统必须回答并留证：

1. 当前市场应配置成长、防御还是现金；
2. 哪个行业/标的有可实现的净优势；
3. 何时进入、买多少、最多亏多少；
4. 何时减仓或退出；
5. 最终赚没赚、利润来自市场、行业、择时、选股还是执行；
6. 哪个策略应该升级、降级或退役。

## 2. 总体架构

```text
原始数据层（带 source / known_at / fetched_at / adjustment）
  → 特征层（只读、可复算）
  → 策略研究层（research / paper / live / retired）
  → 唯一决策引擎（唯一有权产生交易动作）
  → MASTER.md 当前事实与决策
  → 事件与通知
  → 用户实报成交
  → 交易账本与结果归因
  → 策略升级/降级/退役
```

任何 Agent、定时任务和扫描器只能提交事实、候选或信号；不得绕过决策引擎直接产生买卖动作。

## 3. 单一当前事实源：MASTER.md

唯一当前事实文件：`$HOME/.stock-guardian/MASTER.md`。

任何 AI 都可以修改，但必须通过 `state-core.js` 的原子命令或通过校验器验收；直接编辑后必须运行 `state-core.js validate`。文件使用版本号、区块标记和修订号，历史叙事不得混入当前区块。

### 3.1 必备区块

1. `META`：schema_version、revision、updated_at、last_writer；
2. `ACCOUNT`：现金、总资产、数据状态（confirmed / estimated / unknown）；
3. `POSITIONS`：代码、数量、可卖数量、成本、来源、known_at；
4. `ORDERS`：用户明确实报的挂单；
5. `EXECUTIONS`：最新成交事实；
6. `MARKET_REGIME`：市场状态、证据、有效期；
7. `CANDIDATES`：一个标的一个 candidate_id，可挂多个 entry_plan；
8. `ACTIVE_DECISIONS`：唯一现行动作、decision_id、有效期、前提、失效条件；
9. `STRATEGY_REGISTRY`：版本、状态、证据等级、适用周期、最近复核；
10. `DATA_HEALTH`：数据源、新鲜度、缺失与降级；
11. `OPEN_QUESTIONS`：成交价、现金等未确认事实，必须保留 unknown，禁止推算冒充确认。

### 3.2 真相优先级

用户明确成交实报 > 券商/账户导入 > 机器行情估值 > AI 推算。AI 建议永远不等于成交。

`portfolio.md`、`pool.md`、`picks.md`、`watch.conf` 逐步降级为 MASTER.md 生成视图；历史材料保留但不得作为当前事实。

## 4. 数据架构

### 4.1 研究数据湖

研究数据与 MASTER.md 分离，可使用 DuckDB/Parquet/SQLite；每张表必须有：

- `source`；
- `known_at`；
- `fetched_at`；
- `adjustment`（raw/qfq/hfq）；
- `quality_flags`；
- `schema_version`。

### 4.2 必补数据及优先级

P0：

- 全 A 历史日 K：原始与前复权；
- 真实历史股票池（含退市/ST/上市日期，减少幸存者偏差）；
- 停牌、涨跌停、成交额、换手；
- ETF 历史与对应行业/主题映射；
- 指数、市场宽度、成交额、波动率；
- 交易成本参数：最低佣金、ETF/股票税费、滑点。

P1：

- 公告与财报 `known_at`；
- 财务报表及披露时间；
- 行业成分历史；
- 涨停/连板/炸板/晋级率；
- 候选标的分钟 K（至少 5 分钟）。

P2：

- 前向新闻归档；
- 集合竞价数据；
- 更细粒度盘口（只有来源可靠时）。

无法历史穿越的数据不得用于历史回测，只能进入前向 paper 数据集。

## 5. 统一回测契约

所有策略必须共用同一撮合与成本引擎：

- 决策后真实可成交价格；
- T+1 可卖约束；
- 一字涨停买不到、一字跌停卖不掉；
- 停牌顺延；
- 股票与 ETF 不同税费；
- 最低佣金与滑点；
- 容量和成交额限制；
- 冻结历史宇宙；
- 公告/财报时点穿越；
- benchmark 与 cash benchmark；
- walk-forward、年份/regime 分组、参数敏感性、对抗区间；
- 输出净收益、胜率、盈亏比、MDD、Sharpe、换手、成本、beta/alpha、校准曲线。

每个研究产物必须保存：代码版本、数据哈希、参数、随机种子、区间、策略状态、invalidatedBy。

## 6. 只研究三条赚钱主线

### A. 市场状态资产配置

在成长 ETF、防御 ETF、现金之间配置。目标周期 5—10 日。

特征候选：市场宽度、两市成交额、波动率、趋势、风格相对强度、行业扩散、风险事件。输出仓位，不挑神股。

### B. 行业 ETF 轮动

限定高流动性 ETF：机器人、存储/CPO/半导体、银行、红利、医药、黄金和现金。按 5—10 日净收益研究行业强弱、持续性、透支度和切换。

盘中 5 分钟结构仅作为**入场执行优化器**，不能独立创造策略 alpha。

### C. 防御个股质量轮动

研究自由现金流、分红稳定性、盈利稳定性、估值、低波、公告风险、恶化日相对抗跌，持有 5—20 日。华东和大行只是样本，不能由单例推导方法。

其他简单量价、洗盘、固定突破、修复融合等已证伪路线标 `retired`；moneyflow 硬阈值标 `research`；双均线和盘中结构标 `paper`，不得直接称为赚钱方法。

## 7. 决策引擎契约

输入：MASTER.md、市场 regime、策略注册表、候选信号、新闻公告、当前持仓、T+1 可卖量、风险预算、数据健康。

输出最多三个动作，且同一标的同一时点只能有一个最终动作：

- action：BUY / SELL / REDUCE / ADD / HOLD / WATCH；
- code / quantity / price_range；
- max_loss_amount；
- expected_holding_days；
- invalidation；
- targets 与风险收益比；
- strategy_id/version/evidence_level；
- decision_id / signal_ids；
- valid_from / expires_at；
- missing_evidence；
- plain_language_reason。

没有 `live` 策略、数据降级、事实冲突或无法计算风险预算时，只能输出 WATCH/HOLD 或数据事故，不能发买入指令。

## 8. 风险预算

初始研究参数（须由用户确认后进入 live）：

- 单笔计划最大损失：账户 0.5%，约 250 元；
- paper/live 初始试探仓：账户 10%；
- 确认后单方向上限：20%—25%；
- 单一高波动主题上限：30%；
- 防御类合计上限：60%；
- 同时最多 3 个实盘方向；
- 现金是合法配置。

仓位由允许亏损金额和不可执行风险共同决定，禁止凭感觉说“买一万五”。

## 9. 策略晋级门槛

`research → paper`：

- 无未来函数；
- 多个样本外窗口扣费后为正；
- 不依赖单票或单一年份；
- 参数 ±20% 不翻转；
- 对抗区间可解释。

`paper → live`：

- 前向至少 20 个独立信号；
- 净收益、MDD、盈亏比达到预设；
- 概率校准不过度自信；
- 数据质量和执行延迟达标；
- 独立红队通过。

`live → retired`：显著漂移、连续失败、数据源失真或逻辑被市场制度改变。

## 10. 盈亏闭环

必须形成：

`signal_id → decision_id → execution_id → position_change → outcome_id`

Outcome 至少记录：1/3/5/10 日净收益、实际退出、成本、最大有利/不利波动、基准收益、归因（market/sector/timing/selection/execution）、未执行的反事实结果。

没有 outcome 的系统只能报告触发率，不得报告赚钱能力。

## 11. 通知原则

通知不是新的分析入口，只是决策引擎结果的渲染：

- 发生了什么；
- 对账户有什么影响；
- 现在明确做什么；
- 最大可能亏多少钱；
- 哪些证据支持；
- 何时失效；
- 数据与策略版本。

概率只能引用同策略、同口径、同持有期、同 regime 的回测；必须附样本数、样本外结果、成本和数据新鲜度。无匹配样本时明确写“不知道”，禁止挪用 SOXX、单一 K 线或无关概率装饰通知。

## 12. 自动进化循环

每日：数据质量、事实一致性、paper/live 信号与 outcome 更新。

每周：champion/challenger 对账、概率校准、执行延迟、策略漂移。

每月：策略晋级/降级/退役；规则瘦身；研究缺口排序。

AI 可提出和实现 challenger，但不得自动晋级为 live；主代理负责最终审判。

## 13. 实施阶段与验收

### Phase 0：运行止血

- 修 Node cron 绝对路径；
- 暂停危险 timing writer；
- 撤掉写反/重叠 MA 线；
- 清理过期份数口径等旧动作；
- 所有未验证自动买入降为 paper。

验收：cron 真跑、无过期持仓数字、现行硬止损不被删除。

### Phase 1：MASTER.md 与事实迁移

- 实现 `state-core.js`；
- 导入现有事实，冲突列出、不静默选择；
- 原子成交命令；
- 生成兼容视图。

验收：当前持仓/现金/成交只有一份现行值，unknown 保留，重复执行幂等。

### Phase 2：统一数据与回测

- 数据目录与质量报告；
- 统一撮合成本库；
- 旧策略重定级；
- 研究产物元数据化。

### Phase 3：决策引擎与通知收敛

- 所有生产者只 emit；
- 决策引擎唯一出动作；
- dispatcher 唯一发送；
- 冲突/延迟/有效期处理。

### Phase 4：三条研究主线

先资产配置，再行业 ETF 轮动，最后防御个股质量。

### Phase 5：paper 前向与小仓 live

通过门槛后才允许约 10% 试探仓。

## 14. AI 分工与权限

- 主代理：架构、统计口径、策略定义、合并、上线审判；
- HY4：数据盘点、迁移、测试夹具；
- DeepSeek/Kimi：按任务包实现；
- GLM/另一 DeepSeek：独立红队；
- 实现者与裁判不得相同；
- 免费模型仅在隔离 staging 目录工作；
- 未通过主代理验收，不得改生产目录。

当前执行边界：先完成 Phase 0 与 Phase 1，再允许任何新策略或通知功能进入生产。
