# 定时任务配方（供新装机复刻）

> 本文件是逻辑层：零用户数据。朋友拿到 skill 后，让他的 AI 读本文件按相同节奏创建 cron。
> 占位符：`<skills>` = 他的 skills 目录（含 stock-guardian），`$HOME` = 他的用户主目录。
> jobMessage 里的 notify 句指"把结果告知用户"——在带通知工具的平台用通知工具，不带平台的 AI 直接把结论发到对话/群，语义不变。

## 通知通道（结果告知 + 群 webhook 双发）

- 结果告知：每个任务跑完必须把结果告知用户（jobMessage 结尾的强制句保留）；数据拉不到、休市、场景不适用也要说明，不硬凑内容。
- 群机器人（主通道，初始化必问，企微/钉钉/飞书/Bark 任一）：**首次装机时 AI 必须主动问用户要不要配**；要配则让用户把群机器人地址发来，建立 `$HOME/.stock-guardian/webhook.env`（权限 600），内容一行 `WECHAT_WEBHOOK_URL='他的群机器人地址'`（钉钉加签另配 `DINGTALK_SECRET='...'`），随即发一条 tag `测试` 的消息请用户在群里确认送达；此后所有定时场景结果、警报、操作类通知（操作思路/买入/卖出/做T/成交）经 `<skills>/stock-guardian/scripts/notify-webhook.sh` 推群，未配置时自动跳过零影响。规范详见 SKILL.md"群通知通道（webhook 机器人）"节。发送器 v2 自带格式加固：tag 语义 emoji 头、`--title` 自动去重（剥"股票管家"前缀与重复 tag）、正文换行复原（字面 `\n`/`<br>`/两侧非英文字母的裸 n、nn → 真换行）、空正文兜底、超长按行截断保头舍尾——jobMessage 的 `<要点>` 仍按干净 markdown 书写（真实换行、结论加粗、多票分段、风险 `warning` 色），发送器只兜底不代工。
- 分钟级盯盘（可选，推荐）：系统 crontab 加一行 `* * * * * flock -n /tmp/stock-guardian-watch.lock timeout 60 <skills>/stock-guardian/scripts/watch.sh >> $HOME/.stock-guardian/watch.log 2>&1`；A 股价格类触发（规则线/警报线/区间/当日异动——默认 ±3%，watch.conf 写 watch|<code>|pct|<阈值> 按票调，更灵敏 2%、更钝 5% 都行）约 1 分钟内推群。**每次运行写一行心跳到 watch.log**（tail 该文件即可确认 watchdog 活着）。规则分两层：静态线在 `$HOME/.stock-guardian/watch.conf`（格式见文件头注释，与 portfolio.md"盘中警报线"同源同步，改完跑 `<skills>/stock-guardian/scripts/check-sync.sh` 自检，输出 OK=一致、DRIFT=须对齐）；动态线自动读当日 day file 的 `BOX|` 行生成"突破上沿/跌破下沿"规则，`PLAN|` 行的白话动作在触发时原样推给用户（警报只说"该怎么办"，不说"去翻文档"），箱体每天随 10 点箱体确认任务重画自动更新，无需手工维护。**去重语义**：同一触发 30 分钟内不重复轰炸；价格回升后规则重新武装；冷却期内的再次触发不推送但保持武装——"跌破→回升→再跌破"的 V 型里第二次跌破会在冷却结束后照常再报，不会被永久吞掉。

## 跨场景衔接协议（day file 动态档案）

- 动机：每个定时任务都是 isolated 会话，互相看不见。day file 让 10 点画的箱体 11:45 还在、尾盘知道早盘的做T方案、早报接得住凌晨美股结论。
- 位置与生命周期：`$HOME/.stock-guardian/day/YYYY-MM-DD.md`，35 天自动清理，零手工维护。
- 工具：`<skills>/stock-guardian/scripts/day-log.sh`，五个子命令——`read [日期]`（读档案）、`append "场景名" "要点"`（落档，百字内）、`list [N]`（列最近 N 天档案）、`box <代码> <下沿> <上沿>`（记录当日箱体，生成 `BOX|<代码>|<下沿>|<上沿>` 机器行，watchdog 自动变规则）、`plan <代码> "<突破上沿怎么办>" "<跌破下沿怎么办>"`（记录当日预案动作，生成 `PLAN|` 机器行，watchdog 触发警报时原样推给用户）。
- 接入要求：每个定时任务 jobMessage 开头 `read` 衔接今天各场景结论（不重复已说过的），干完 `append` 落档要点；箱体确认任务另跑 `box`；早报另读前一交易日档案衔接昨日尾盘未了结事项；watchdog 警报自动落档。本仓库 jobMessage 模板（下节）已内置该协议，直接照抄即可。

## jobMessage 模板

- 早报：你是股票管家（skill: stock-guardian）。执行早报任务：1) 读 $HOME/.stock-guardian/portfolio.md 拿到持仓、规则线、监控代码表（每个海外代码都写了为什么盯它的关联理由）；运行 <skills>/stock-guardian/scripts/day-log.sh read 衔接今天凌晨美股三报结论，再 day-log.sh list 1 读前一交易日档案衔接昨日尾盘未了结事项，不重复已说过的；2) 运行 <skills>/stock-guardian/scripts/monitor.sh 拉取隔夜海外组与A股持仓行情（休市/无数据组自行判断并说明）；3) 按档案关联逻辑用大白话解读隔夜海外市场对用户每只持仓的传导含义（推理不出关联的不硬扯），对照规则线逐票检查，给出今日动作清单，术语就地解释；4) 完成后 day-log.sh append "早报" 落档百字内要点；5) 无档案则通知用户先按模板初始化。用 notify 工具发送，标题"股票管家·早报"。无实质触发时正文精简。你必须使用 notify 工具主动告知我结果，无论成功还是异常。
- 亚太早巡：执行亚太早巡任务：1) 读 $HOME/.stock-guardian/portfolio.md 监控代码表，找出亚太组（日韩股/汇率类代码）；没有亚太组则 notify 一句话"当前持仓无亚太关联，本场景休眠"并结束；2) 运行 <skills>/stock-guardian/scripts/monitor.sh group:亚太 拉取数据；3) 大白话解读昨日收盘：每只标的按档案关联逻辑说清"这对用户哪只持仓、什么链条有传导"，日元骤升（套息平仓风险）要点名；数据日期非当天即休市，一行说明不硬凑；单票当日异动超阈值（默认 ±3%）标注异动；先 day-log.sh read 衔接今天已有结论（含凌晨美股收盘盖棺）不重复；4) 完成后 day-log.sh append "亚太早巡" 落档要点；5) 用 notify 工具发送，标题"股票管家·亚太早巡"。你必须使用 notify 工具主动告知我结果，无论成功还是异常。
- 开盘快照：执行开盘快照任务：1) 读 $HOME/.stock-guardian/portfolio.md 拿到持仓、挂单计划、规则线、监控代码表；运行 <skills>/stock-guardian/scripts/day-log.sh read 衔接早报/亚太早巡结论不重复；2) 运行 <skills>/stock-guardian/scripts/monitor.sh group:A股 拉取持仓与挂单票行情；3) 开盘快照核心交付：每只票高开/低开/平开 + 开盘5分钟量能定性（大白话：今天开盘是抢着买还是抢着卖），对挂单计划（如有）判断今日挂单价能否够到，对照规则线标注距最近的触发价还有多远；4) 用户操作时段以档案"纪律参数"节为准（默认起点：10 点前不操作、9:30-10:00 只画箱体；用户定了别的时段就按他的来），在用户预设操作窗之外的时段只给观察结论不给操作指令，明确说明"箱体要等 10 点才成型"；5) 完成后 day-log.sh append "开盘快照" 落档要点；6) 用 notify 工具发送，标题"股票管家·开盘快照"，无实质内容时正文精简到三行内。你必须使用 notify 工具主动告知我结果，无论成功还是异常。
- 箱体确认：执行箱体确认任务：1) 读 $HOME/.stock-guardian/portfolio.md 拿到持仓、挂单计划、规则线、盘中警报线、做T判断参考、监控代码表；运行 <skills>/stock-guardian/scripts/day-log.sh read 衔接今天已有结论；2) 运行 <skills>/stock-guardian/scripts/monitor.sh group:A股 拉取行情，并用 westock-data 的 kline 子命令拉持仓与挂单票的分时/当日数据；3) 先按 rules.md 市场状态框架给今日市场状态定档（用当日涨跌家数、量能、指数与 5 日线关系等证据组合判断，不信单一指标），状态是后续所有结论的前缀；同时对照档案各票"画线依据"做结构质变检查（rules.md 动态重估协议：价格进入从未画线的新区/量价较昨日质变/持有理由动摇）——命中的票跳出规则线从零重估，明说档案线与新分析的分歧并提议改线，不拿旧格子硬套新盘面；4) 箱体确认核心交付（操作时段以档案"纪律参数"节为准，默认起点：10 点前只画箱体不操作、10 点整是当日第一个决策点；用户定了别的时段就按他的来）：对每只票用开盘 30 分钟的最高/最低价画出当日箱体（大白话解释：箱体=今天价格活动的房间，上沿=天花板，下沿=地板），标注当前价站在箱体哪个位置，给三段式预案：突破上沿怎么办（挂单价是否需要上调/追不追的纪律提醒）、跌破下沿怎么办（对照规则线与警报线）、箱体内怎么办——做T按 rules.md"做T判断"节自主判断（无授权开关）：形态值得（震荡市、贴箱体沿、日内空间够）就给"下沿接、上沿抛"方案并讲透判断依据，不值得就一句话讲清为什么不值、等 14:45 尾盘决策；画完每只票跑 day-log.sh box <代码> <下沿> <上沿> 与 day-log.sh plan <代码> "<突破上沿怎么办>" "<跌破下沿怎么办>"（此后 watchdog 分钟级盯突破/跌破——动态警报线；PLAN 两句白话动作在警报触发时原样推给用户，必须是带具体价格的动作句如"回踩7.70-7.72不破可加一档""收盘破7.35无条件清仓"，禁止写"对照预案/rules.md"这类让用户自己翻文档的话，动作文本里不要用竖线|字符）；5) 对挂单计划判断挂单价与当前箱体的相对位置，够不到就明说"今日大概率错过，错过不亏钱"；6) 完成后 day-log.sh append "箱体确认" 落档要点（含当日箱体与三段式预案结论）；7) 用 notify 工具发送，标题"股票管家·箱体确认"。你必须使用 notify 工具主动告知我结果，无论成功还是异常。

## 装机注意事项

- 半场/收盘报表达式是 2-6（跨午夜落在次日），不是 1-5
