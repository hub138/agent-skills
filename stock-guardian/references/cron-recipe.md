# 定时任务配方（供新装机复刻）

> 本文件是逻辑层：零用户数据。朋友拿到 skill 后，让他的 AI 读本文件按相同节奏创建 cron。
> 占位符：`<skills>` = 他的 skills 目录（含 stock-guardian），`$HOME` = 他的用户主目录。
> jobMessage 里的 notify 句指"把结果告知用户"——在带通知工具的平台用通知工具，不带平台的 AI 直接把结论发到对话/群，语义不变。

## 通知通道（结果告知 + 群 webhook 双发）

- 结果告知：每个任务跑完必须把结果告知用户（jobMessage 结尾的强制句保留）；数据拉不到、休市、场景不适用也要说明，不硬凑内容。
- 群机器人（主通道，初始化必问，企微/钉钉/飞书/Bark 任一）：**首次装机时 AI 必须主动问用户要不要配**；要配则让用户把群机器人地址发来，建立 `$HOME/.stock-guardian/webhook.env`（权限 600），内容一行 `WECHAT_WEBHOOK_URL='他的群机器人地址'`（钉钉加签另配 `DINGTALK_SECRET='...'`），随即发一条 tag `测试` 的消息请用户在群里确认送达；此后所有定时场景结果、警报、操作类通知（操作思路/买入/卖出/做T/成交）经 `<skills>/stock-guardian/scripts/notify-webhook.sh` 推群，未配置时自动跳过零影响。规范详见 SKILL.md"群通知通道（webhook 机器人）"节。发送器 v2 自带格式加固：tag 语义 emoji 头、`--title` 自动去重（剥"股票管家"前缀与重复 tag）、正文换行复原（字面 `\n`/`<br>`/两侧非英文字母的裸 n、nn → 真换行）、空正文兜底、超长按行截断保头舍尾——jobMessage 的 `<要点>` 仍按干净 markdown 书写（真实换行、结论加粗、多票分段、风险 `warning` 色），发送器只兜底不代工。
- 分钟级盯盘（可选，推荐）：系统 crontab 加一行 `* * * * * flock -n /tmp/stock-guardian-watch.lock timeout 60 <skills>/stock-guardian/scripts/watch.sh >> $HOME/.stock-guardian/watch.log 2>&1`；A 股价格类触发（规则线/警报线/区间/当日异动——默认 ±3%，watch.conf 写 watch|<code>|pct|<阈值> 按票调，更灵敏 2%、更钝 5% 都行）约 1 分钟内推群。**每次运行写一行心跳到 watch.log**（tail 该文件即可确认 watchdog 活着）。规则分两层：静态线在 `$HOME/.stock-guardian/watch.conf`（格式见文件头注释，与 portfolio.md"盘中警报线"同源同步，改完跑 `<skills>/stock-guardian/scripts/check-sync.sh` 自检，输出 OK=一致、DRIFT=须对齐）；动态线自动读当日 day file 的 `BOX|` 行生成"突破上沿/跌破下沿"规则，`PLAN|` 行的白话动作在触发时原样推给用户（警报只说"该怎么办"，不说"去翻文档"），箱体每天随 10 点箱体确认任务重画自动更新，无需手工维护。**去重语义**：同一触发 30 分钟内不重复轰炸；价格回升后规则重新武装；冷却期内的再次触发不推送但保持武装——"跌破→回升→再跌破"的 V 型里第二次跌破会在冷却结束后照常再报，不会被永久吞掉。

## 跨场景衔接协议（day file 动态档案）

- 动机：每个定时任务都是 isolated 会话，互相看不见。day file 让 10 点画的箱体 11:45 还在、尾盘知道早盘的做T方案、早报接得住凌晨美股结论。
- 位置与生命周期：`$HOME/.stock-guardian/day/YYYY-MM-DD.md`，35 天自动清理，零手工维护。
- 工具：`<skills>/stock-guardian/scripts/day-log.sh`，五个子命令——`read [日期]`（读档案）、`append "场景名" "要点"`（落档，百字内）、`list [N]`（列最近 N 天档案）、`box <代码> <下沿> <上沿>`（记录当日箱体，生成 `BOX|<代码>|<下沿>|<上沿>` 机器行，watchdog 自动变规则）、`plan <代码> "<突破上沿怎么办>" "<跌破下沿怎么办>"`（记录当日预案动作，生成 `PLAN|` 机器行，watchdog 触发警报时原样推给用户）。
- 接入要求：每个定时任务 jobMessage 开头 `read` 衔接今天各场景结论（不重复已说过的），干完 `append` 落档要点；箱体确认任务另跑 `box`；早报另读前一交易日档案衔接昨日尾盘未了结事项；watchdog 警报自动落档。本仓库 jobMessage 模板（下节）已内置该协议，直接照抄即可。

- 半场/收盘报表达式是 2-6（跨午夜落在次日），不是 1-5
- 冬夏令时切换日在 cron 表层面看不出对错，装机时先确认当前处于哪个时段再选时间列

- day file（$HOME/.stock-guardian/day/）是跨场景衔接的运行时数据，35 天自动清理，装机时不用迁移旧机器数据，第一天从空档案起步即可
